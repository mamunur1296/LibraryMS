### প্রশ্ন ১: SQL-এ `SELECT INTO` স্টেটমেন্ট কী? কীভাবে ব্যবহার করতে হয়?

**উত্তর:**
**`SELECT INTO`** হলো এমন একটি SQL কমান্ড যার মাধ্যমে একটি বিদ্যমান টেবিল থেকে ডেটা কুয়েরি করে এনে **অটোমেটিক্যালি একটি নতুন টেবিল তৈরি করা হয়** এবং সেই ডেটা নতুন টেবিলে কপি করা হয়। 

*   **বৈশিষ্ট্য:** নতুন টেবিলটি আগে থেকে ডেটাবেসে থাকতে হয় না। ডেটাবেস ইঞ্জিন নিজেই কলামের ডেটাটাইপ দেখে টেবিলটি তৈরি করে নেয়।

#### সিনট্যাক্স:
```sql
SELECT Column1, Column2 
INTO NewTable 
FROM ExistingTable 
WHERE Condition;
```

#### বাস্তব উদাহরণ:
১. **পুরো টেবিল ব্যাকআপ নেওয়া:** `Employees` টেবিলের একটি ব্যাকআপ কপি তৈরি করতে:
```sql
SELECT * INTO Employees_Backup FROM Employees;
```
২. **শুধু স্ট্রাকচার কপি করা (ডেটা ছাড়া):** যদি আপনি চান শুধু টেবিলের কলামগুলো কপি হবে কিন্তু কোনো ডেটা ঢুকবে না, তবে `WHERE 1 = 0` (যা সবসময় মিথ্যা) শর্ত দিন:
```sql
SELECT * INTO Empty_Employees_Table FROM Employees WHERE 1 = 0;
```

### প্রশ্ন ২: SQL-এ `INSERT INTO SELECT` স্টেটমেন্ট কী? `SELECT INTO` এবং `INSERT INTO SELECT`-এর মধ্যে মূল পার্থক্য কী?

**উত্তর:**
**`INSERT INTO SELECT`** স্টেটমেন্টটি ব্যবহার করে একটি টেবিল থেকে ডেটা তুলে এনে **আগে থেকে তৈরি থাকা অন্য একটি টেবিলে** ইনসার্ট (Insert) বা কপি করা হয়। 

*   **বৈশিষ্ট্য:** এক্ষেত্রে টার্গেট বা নতুন টেবিলটি ডেটাবেসে অবশ্যই আগে থেকে তৈরি থাকতে হবে।

#### সিনট্যাক্স:
```sql
INSERT INTO TargetTable (Column1, Column2)
SELECT Column1, Column2 
FROM SourceTable
WHERE Condition;
```

#### SELECT INTO বনাম INSERT INTO SELECT-এর মূল পার্থক্য:

| বৈশিষ্ট্য | SELECT INTO | INSERT INTO SELECT |
| :--- | :--- | :--- |
| **টেবিলের উপস্থিতি** | টার্গেট টেবিলটি আগে থেকে থাকা যাবে না (অটোমেটিক তৈরি হয়)। | টার্গেট টেবিলটি অবশ্যই আগে থেকে তৈরি থাকতে হবে। |
| **ব্যবহারের ক্ষেত্র** | দ্রুত টেবিল ব্যাকআপ নেওয়া বা টেম্পোরারি টেবিল তৈরির জন্য। | ইতিমধ্যে থাকা টেবিলে অন্য টেবিলের ডেটা অ্যাপেন্ড বা যোগ করার জন্য। |
| **কলাম ম্যাপিং** | সোর্স টেবিলের কলামের নাম ও টাইপ সরাসরি কপি হয়। | টার্গেট ও সোর্স টেবিলের কলামের সিকোয়েন্স ও ডেটাটাইপ মিলতে হবে। |

### প্রশ্ন ৩: SQL Server-এ সবচেয়ে বেশি ব্যবহৃত String Functions-গুলো কী কী? (উদাহরণসহ)

**উত্তর:**
SQL Server-এ স্ট্রিং বা টেক্সট ডেটা ম্যানিপুলেট বা সাইজ করার জন্য অনেকগুলো ফাংশন রয়েছে। নিচে সবচেয়ে প্রয়োজনীয় ৫টি ফাংশন আলোচনা করা হলো:

১. **LEN(string):** স্ট্রিংয়ে মোট কতটি ক্যারেক্টার আছে (দৈর্ঘ্য) তা বের করে (শেষের স্পেস বাদে)।
```sql
SELECT LEN('Hello World'); -- আউটপুট: 11
```
২. **SUBSTRING(string, start, length):** একটি স্ট্রিংয়ের মাঝখান থেকে নির্দিষ্ট অংশ কেটে নিয়ে আসে।
```sql
SELECT SUBSTRING('Programentor', 1, 5); -- আউটপুট: Progr (১ম পজিশন থেকে ৫টি অক্ষর)
```
৩. **REPLACE(string, old_string, new_string):** স্ট্রিংয়ের ভেতরের কোনো নির্দিষ্ট টেক্সট পরিবর্তন করে অন্য টেক্সট বসায়।
```sql
SELECT REPLACE('I love SQL Server', 'SQL Server', '.NET'); -- আউটপুট: I love .NET
```
৪. **LTRIM() এবং RTRIM():** স্ট্রিংয়ের যথাক্রমে বাম দিকের (Left) এবং ডান দিকের (Right) অতিরিক্ত খালি জায়গা বা স্পেস মুছে ফেলে।
```sql
SELECT LTRIM('   Hello'); -- আউটপুট: 'Hello'
```
৫. **UPPER() এবং LOWER():** টেক্সটকে বড় হাতের (UPPERCASE) বা ছোট হাতের (lowercase) অক্ষরে রূপান্তর করে।
```sql
SELECT UPPER('karim'); -- আউটপুট: KARIM
```

### প্রশ্ন ৪: SQL-এ GUID (Globally Unique Identifier) বা UNIQUEIDENTIFIER কী? এর ব্যবহার ও সুবিধা কী?

**উত্তর:**
**GUID** (Globally Unique Identifier) হলো একটি ১৬-বাইটের (১২৮ বিট) অদ্বিতীয় বাইনারি নাম্বার, যা বিশ্বজুড়ে ইউনিক হওয়ার গ্যারান্টি দেয়। SQL Server-এ এর ডেটাটাইপকে **`UNIQUEIDENTIFIER`** বলা হয়। 

*   **GUID দেখতে কেমন:** `6F9619FF-8B86-D011-B42D-00C04FC964FF` (৩২টি হেক্সাডেসিমেল ক্যারেক্টার এবং ৪টি হাইফেন)।
*   **তৈরির নিয়ম:** SQL Server-এ নতুন GUID তৈরি করতে **`NEWID()`** ফাংশন ব্যবহার করা হয়।

#### সিনট্যাক্স ও উদাহরণ:
```sql
CREATE TABLE Users (
    UserID UNIQUEIDENTIFIER DEFAULT NEWID() PRIMARY KEY,
    Username VARCHAR(50)
);

INSERT INTO Users (Username) VALUES ('Rahim');
```

#### GUID ব্যবহারের সুবিধা ও অসুবিধা:
*   **সুবিধা (Pros):** 
    ১. **ডিস্ট্রিবিউটেড সিস্টেম:** যদি একাধিক সার্ভার বা নোডে আলাদাভাবে ডেটা ইনসার্ট করা হয়, তবে মার্জ করার সময় আইডি ডুপ্লিকেট হওয়ার কোনো সুযোগ থাকে না।
    ২. **সিকিউরিটি:** আইডি প্রেডিক্ট করা যায় না (যেমন: সাধারণ ইন্টিজার ১, ২, ৩ হলে হ্যাকার পরবর্তী আইডি ৪ গেস করতে পারে, GUID-তে তা অসম্ভব)।
*   **অসুবিধা (Cons):** 
    ১. সাইজ অনেক বড় (১৬ বাইট, যেখানে INT ৪ বাইট)। ফলে ইনডেক্সিং স্লো হয়।
    ২. ফিজিক্যালি ডেটা সর্ট করার সময় পারফরম্যান্স ড্রপ করে।

### প্রশ্ন ৫: SQL-এ `MERGE` Statement কী? এটি কীভাবে কাজ করে? (বাস্তব উদাহরণসহ)

**উত্তর:**
**`MERGE`** হলো একটি অত্যন্ত শক্তিশালী স্টেটমেন্ট (যা Upsert নামেও পরিচিত)। এর মাধ্যমে একটি সোর্স টেবিল ও টার্গেট টেবিলের ডেটা তুলনা করে একই সাথে **`INSERT`**, **`UPDATE`** এবং **`DELETE`** অপারেশন চালানো যায়।

#### এটি যেভাবে কাজ করে:
*   যদি সোর্সের ডেটা টার্গেট টেবিলে ম্যাচ করে (`WHEN MATCHED`) -> টার্গেট টেবিল **UPDATE** করো।
*   যদি সোর্সের ডেটা টার্গেট টেবিলে না থাকে (`WHEN NOT MATCHED BY TARGET`) -> টার্গেটে **INSERT** করো।
*   যদি টার্গেটের ডেটা সোর্স টেবিলে না থাকে (`WHEN NOT MATCHED BY SOURCE`) -> টার্গেট থেকে **DELETE** করো।

#### বাস্তব উদাহরণ:
ধরি, আমাদের একটি মূল `Products` (Target) টেবিল এবং প্রতিদিনের নতুন আপডেট আসা `UpdatedProducts` (Source) টেবিল আছে।

```sql
MERGE Products AS Target
USING UpdatedProducts AS Source
ON (Target.ProductID = Source.ProductID)

-- ১. ম্যাচ করলে প্রাইস আপডেট করো
WHEN MATCHED THEN
    UPDATE SET Target.Price = Source.Price

-- ২. ম্যাচ না করলে নতুন প্রোডাক্ট ইনসার্ট করো
WHEN NOT MATCHED BY TARGET THEN
    INSERT (ProductID, ProductName, Price)
    VALUES (Source.ProductID, Source.ProductName, Source.Price)

-- ৩. সোর্সে না থাকলে টার্গেট থেকে ডিলিট করো (ঐচ্ছিক)
WHEN NOT MATCHED BY SOURCE THEN
    DELETE;
```

### প্রশ্ন ৬: SQL Server-এ User Defined Functions (UDF) কী? Scalar Functions কীভাবে তৈরি করতে হয়?

**উত্তর:**
**User Defined Functions (UDF)** হলো ব্যবহারকারীর তৈরি করা নিজস্ব ফাংশন। Stored Procedure-এর মতোই এতে নির্দিষ্ট কিছু SQL লজিক লেখা থাকে। UDF-এর সবচেয়ে বড় বৈশিষ্ট্য হলো এটি রান করার পর একটি সুনির্দিষ্ট মান বা টেবিল অবশ্যই **রিটার্ন (Return)** করে।

UDF প্রধানত দুই প্রকার:
১. **Scalar Functions:** যা শুধুমাত্র একটি একক বা সিঙ্গেল ভ্যালু (যেমন: INT, VARCHAR, DATE) রিটার্ন করে।
২. **Table-Valued Functions (TVF):** যা একটি সম্পূর্ণ ডেটা টেবিল রিটার্ন করে।

#### Scalar Function তৈরির সিনট্যাক্স ও উদাহরণ:
ধরুন, আমরা একটি ফাংশন তৈরি করব যা প্রোডাক্টের মূল দাম ইনপুট হিসেবে নিলে ১০% ভ্যাট (VAT) যোগ করে মোট দাম হিসাব করে দেবে।

```sql
CREATE FUNCTION fn_CalculateVat (
    @Price DECIMAL(18,2)
)
RETURNS DECIMAL(18,2) -- রিটার্ন টাইপ
AS
BEGIN
    DECLARE @TotalWithVat DECIMAL(18,2);
    SET @TotalWithVat = @Price + (@Price * 0.10);
    RETURN @TotalWithVat; -- মান রিটার্ন করা হলো
END;
```

#### কীভাবে ব্যবহার করতে হয়:
UDF কল করার সময় নামের আগে অবশ্যই স্কিমা নেম (ডিফল্টভাবে `dbo.`) লিখতে হয়:
```sql
SELECT ProductName, Price, dbo.fn_CalculateVat(Price) AS PriceWithVat 
FROM Products;
```

### প্রশ্ন ৭: SQL Server-এ Inline Table-Valued Function (ILTVF) কী এবং কীভাবে তৈরি করতে হয়?

**উত্তর:**
**Inline Table-Valued Function (ILTVF)** হলো এমন এক ধরনের ফাংশন যা আউটপুট হিসেবে একটি **টেবিল (Set of Rows)** রিটার্ন করে। 

*   **বৈশিষ্ট্য:** এই ফাংশনের ভেতরে কোনো `BEGIN...END` ব্লক থাকে না। এটি শুধুমাত্র একটি একক `SELECT` কোয়েরি ধারণ করে এবং সেই কোয়েরির রেজাল্টটি সরাসরি টেবিল আকারে রিটার্ন করে। এটি দেখতে অনেকটা প্যারামিটারাইজড ভিউ (Parameterized View)-এর মতো।

#### সিনট্যাক্স ও উদাহরণ:
ধরুন, আমরা একটি ফাংশন তৈরি করব যাকে নির্দিষ্ট কোনো বিভাগের (Department) নাম দিলে সে ওই বিভাগের সকল স্টুডেন্টদের তালিকা টেবিল আকারে ফেরত দেবে।

```sql
CREATE FUNCTION fn_GetStudentsByDept (
    @DeptName VARCHAR(50)
)
RETURNS TABLE -- এটি টেবিল রিটার্ন করবে
AS
RETURN (
    -- শুধুমাত্র একটি SELECT কোয়েরি থাকবে, কোনো BEGIN/END থাকবে না
    SELECT StudentID, Name, DeptID 
    FROM Students 
    WHERE Department = @DeptName
);
```

#### কীভাবে ব্যবহার করতে হয়:
যেহেতু এটি টেবিল রিটার্ন করে, তাই একে সাধারণ টেবিলের মতোই `FROM` ক্লজে ব্যবহার করা যায় এবং এর সাথে JOIN-ও করা সম্ভব:
```sql
SELECT * FROM dbo.fn_GetStudentsByDept('CSE');
```

### প্রশ্ন ৮: SQL Server-এ Multi-Statement Table-Valued Function (MSTVF) কী? Inline এবং Multi-Statement Table-Valued Function-এর মধ্যে মূল পার্থক্য কী?

**উত্তর:**
**Multi-Statement Table-Valued Function (MSTVF)** হলো এমন একটি টেবিল-ভ্যালুড ফাংশন যার ভেতরে একাধিক SQL স্টেটমেন্ট বা জটিল লজিক (যেমন: লুপ, কন্ডিশনাল ইফ-এলস) লেখা যায়। 

*   **বৈশিষ্ট্য:** এখানে রিটার্ন করা টেবিলের স্ট্রাকচারটি আগেই ডিক্লেয়ার বা তৈরি করে দিতে হয় এবং `BEGIN...END` ব্লকের ভেতরে লজিক লিখে ডেটা ওই ডিক্লেয়ার করা টেবিলে ইনসার্ট করতে হয়।

#### সিনট্যাক্স ও উদাহরণ:
```sql
CREATE FUNCTION fn_GetActiveEmployees()
RETURNS @TempEmpTable TABLE (  -- রিটার্ন টেবিলের স্ট্রাকচার ডিক্লেয়ারেশন
    EmpID INT,
    Name VARCHAR(50),
    Status VARCHAR(20)
)
AS
BEGIN
    -- এখানে একাধিক স্টেটমেন্ট ও লজিক লেখা যায়
    INSERT INTO @TempEmpTable
    SELECT EmpID, Name, 'Active' 
    FROM Employees 
    WHERE ResignedDate IS NULL;
    
    RETURN; -- কোনো ভেরিয়েবল ছাড়াই শুধু RETURN লিখতে হয়
END;
```

#### Inline (ILTVF) বনাম Multi-Statement (MSTVF) এর মূল পার্থক্য:

| বৈশিষ্ট্য | Inline TVF (ILTVF) | Multi-Statement TVF (MSTVF) |
| :--- | :--- | :--- |
| **BEGIN...END ব্লক** | থাকে না। | অবশ্যই থাকতে হবে। |
| **টেবিল স্ট্রাকচার ডিক্লেয়ার** | করতে হয় না (SELECT কুয়েরি নিজেই ঠিক করে)। | অবশ্যই রিটার্ন টেবিলের স্কিমা নির্দিষ্ট করে দিতে হবে। |
| **স্টেটমেন্টের সংখ্যা** | কেবল একটি `SELECT` স্টেটমেন্ট থাকে। | একাধিক স্টেটমেন্ট এবং জটিল লজিক থাকতে পারে। |
| **পারফরম্যান্স** | অত্যন্ত দ্রুত (SQL Server একে ইন্টারনাল জয়েন হিসেবে অপ্টিমাইজ করে)। | তুলনামূলক স্লো (এটি মেমরিতে টেবিল ভেরিয়েবল জেনারেট করে কাজ করে)। |

---

### প্রশ্ন ৯: Stored Procedure এবং Function (UDF)-এর মধ্যে মূল পার্থক্য কী? (Stored Procedure VS Function)

**উত্তর:**
Stored Procedure (SP) এবং Function (UDF) উভয়ই ডেটাবেসে কোড রিইউজ করার জন্য ব্যবহৃত হলেও এদের কাজের উদ্দেশ্য সম্পূর্ণ ভিন্ন।

#### মূল পার্থক্যসমূহ:

| বৈশিষ্ট্য | Stored Procedure (SP) | Function (UDF) |
| :--- | :--- | :--- |
| **ভ্যালু রিটার্ন** | এটি মান রিটার্ন করতেও পারে, আবার নাও করতে পারে। | এটি অবশ্যই একটি মান (Scalar) বা টেবিল (TVF) রিটার্ন করবে। |
| **কোয়েরির ভেতরে ব্যবহার** | `SELECT` কুয়েরির ভেতরে সরাসরি ব্যবহার করা যায় না। | `SELECT` বা `WHERE` ক্লজের ভেতরে সরাসরি ব্যবহার করা যায়। |
| **DML অপারেশন** | প্রসিডিউরের ভেতরে `INSERT`, `UPDATE`, `DELETE` চালানো যায়। | ফাংশনের ভেতরে টেবিল মডিফাই করা যায় না (ReadOnly)। |
| **প্যারামিটার টাইপ** | Input এবং Output উভয় প্যারামিটার সাপোর্ট করে। | শুধুমাত্র Input প্যারামিটার সাপোর্ট করে। |
| **Transaction হ্যান্ডলিং** | ভেতরে Transaction এবং Try-Catch ব্যবহার করা যায়। | ভেতরে কোনো Transaction বা Try-Catch ব্যবহার করা যায় না। |

---

### প্রশ্ন ১০: DDL Triggers কী? এটি কীভাবে এবং কেন ব্যবহার করা হয়? (সিনট্যাক্সসহ)

**উত্তর:**
**DDL Triggers** হলো এমন ট্রিগার যা ডেটাবেসের স্ট্রাকচার পরিবর্তনের সময় (যেমন: `CREATE TABLE`, `ALTER TABLE`, `DROP TABLE`) স্বয়ংক্রিয়ভাবে ফায়ার হয়।

#### কেন ব্যবহার করা হয়:
১. **ডেটাবেস প্রোটেকশন:** ভুলবশত বা অনুমতি ছাড়া কোনো গুরুত্বপূর্ণ টেবিল বা ভিউ ড্রপ (Drop) করা রোধ করতে।
২. **অডিটিং ও মনিটরিং:** কে কখন ডেটাবেসের স্কিমা পরিবর্তন করেছে তার লগ রেকর্ড রাখতে।

#### টেবিল ড্রপ করা বন্ধ করার উদাহরণ (ROLLBACK):
```sql
CREATE TRIGGER trgPreventDropTable
ON DATABASE
FOR DROP_TABLE, ALTER_TABLE -- কোন কোন ইভেন্টের জন্য
AS
BEGIN
    PRINT 'You cannot DROP or ALTER tables in this database!';
    ROLLBACK; -- ট্রানজেকশন রোলব্যাক করে পরিবর্তনটি বাতিল করা হলো
END;
```

---

### প্রশ্ন ১১: Server-Scoped DDL Triggers এবং Database-Scoped DDL Triggers-এর মধ্যে পার্থক্য কী?

**উত্তর:**
DDL Triggers তাদের কাজের পরিধি বা স্কোপ অনুযায়ী দুই প্রকার হতে পারে:

১. **Database-Scoped DDL Triggers:**
    *   **ব্যাখ্যা:** এই ট্রিগারগুলো শুধুমাত্র একটি সুনির্দিষ্ট ডেটাবেসের স্কিমা ইভেন্টের ওপর কাজ করে (যেমন: `DROP_TABLE`, `ALTER_VIEW`)।
    *   **তৈরি করার কিওয়ার্ড:** `ON DATABASE`
    *   *ব্যবহার:* নির্দিষ্ট ডেটাবেসের টেবিল সুরক্ষিত রাখতে।

২. **Server-Scoped DDL Triggers:**
    *   **ব্যাখ্যা:** এই ট্রিগারগুলো পুরো SQL Server ইনস্ট্যান্সের ওপর কাজ করে। এর আওতায় থাকা যেকোনো ডেটাবেসে পরিবর্তন আনলে এটি ট্রিগার হবে।
    *   **তৈরি করার কিওয়ার্ড:** `ON ALL SERVER`
    *   *ব্যবহার:* মূলত গ্লোবাল ইভেন্ট যেমন— নতুন ডেটাবেস তৈরি করা (`CREATE_DATABASE`), নতুন লগইন আইডি তৈরি বা ডিলিট করা (`DROP_LOGIN`) ট্র্যাকিং করার জন্য এটি ব্যবহৃত হয়।

---

### প্রশ্ন ১২: SQL-এ Temporary Tables (অস্থায়ী টেবিল) কী? Local Temporary Table কীভাবে কাজ করে?

**উত্তর:**
**Temporary Tables** (বা সংক্ষেপে **Temp Tables**) হলো এমন সাময়িক টেবিল যা ডেটাবেসের বিশেষ সিস্টেম ডেটাবেস **`tempdb`**-তে সাময়িকভাবে তৈরি হয়। জটিল কোয়েরি করার সময় বড় ডেটাসেটকে ফিল্টার করে কিছুক্ষণের জন্য স্টোর করে রাখার জন্য এটি ব্যবহৃত হয়।

#### Local Temporary Table (লোকাল টেম্পোরারি টেবিল):
*   **চেনার উপায়:** নামের শুরুতে একটি হ্যাশ চিহ্ন **`#`** থাকে (যেমন: `#TempStudents`)।
*   **লাইফসাইকেল ও স্কোপ:** 
    *   এটি শুধুমাত্র যে ইউজার বা কানেকশন (Query Window) এটি তৈরি করেছে, সেখানে অ্যাক্সেস করা যায়। অন্য কোনো উইন্ডো থেকে এটি দেখা যাবে না।
    *   উইন্ডো বা সেশনটি বন্ধ করার সাথে সাথে টেবিলটি মেমরি থেকে স্বয়ংক্রিয়ভাবে মুছে যায়।

#### সিনট্যাক্স ও উদাহরণ:
```sql
-- লোকাল টেম্প টেবিল তৈরি
CREATE TABLE #TempStudents (
    ID INT,
    Name VARCHAR(50)
);

-- ডেটা ইনসার্ট এবং রিড
INSERT INTO #TempStudents VALUES (1, 'Rahim');
SELECT * FROM #TempStudents;

-- ম্যানুয়ালি ড্রপ করা (বেস্ট প্র্যাকটিস)
DROP TABLE #TempStudents;
```

### প্রশ্ন ১৩: SQL-এ Global Temporary Table কী? এটি Local Temporary Table-এর চেয়ে কীভাবে আলাদা?

**উত্তর:**
**Global Temporary Table** হলো এমন সাময়িক টেবিল যা তৈরি করার পর ডেটাবেসের যেকোনো সেশন বা উইন্ডো থেকে অ্যাক্সেস করা যায়।

*   **চেনার উপায়:** নামের শুরুতে দুটি হ্যাশ চিহ্ন **`##`** থাকে (যেমন: `##GlobalUsers`)।

#### Local বনাম Global Temporary Table এর মূল পার্থক্য:

| বৈশিষ্ট্য | Local Temp Table (`#`) | Global Temp Table (`##`) |
| :--- | :--- | :--- |
| **চিহ্ন** | একটি `#` দিয়ে শুরু হয়। | দুটি `##` দিয়ে শুরু হয়। |
| **স্কোপ (দৃশ্যমানতা)** | শুধুমাত্র তৈরি করা সেশনে দৃশ্যমান। | সব ইউজারের সেশন থেকে অ্যাক্সেস করা যায়। |
| **ডিলিট হওয়ার আচরণ** | সেশন ক্লোজ হলে সাথে সাথে ডিলিট হয়। | এটি তৈরি করা সেশন ক্লোজ হওয়ার পর, অন্য কোনো সেশনে যদি এটি সচল থাকে তবে কাজ শেষ হওয়া মাত্র ডিলিট হয়। |

---

### প্রশ্ন ১৪: SQL Server-এ `CAST` Function কী? কীভাবে ডেটাটাইপ রূপান্তর (Type Casting) করতে হয়?

**উত্তর:**
**`CAST`** হলো ANSI SQL স্ট্যান্ডার্ড মেনে তৈরি একটি ফাংশন, যা দিয়ে একটি ডেটার ডেটাটাইপকে অন্য ডেটাটাইপে রূপান্তর (Casting) করা যায় (যেমন: সংখ্যাকে টেক্সটে রূপান্তর)।

#### সিনট্যাক্স:
```sql
CAST ( expression AS target_data_type )
```

#### উদাহরণ:
১. **Integer থেকে String-এ রূপান্তর:**
```sql
SELECT 'Total count is: ' + CAST(100 AS VARCHAR(5)); 
-- আউটপুট: Total count is: 100
```
২. **Decimal থেকে Integer-এ রূপান্তর (ভগ্নাংশ বাদ দেওয়া):**
```sql
SELECT CAST(95.65 AS INT); -- আউটপুট: 95
```

### প্রশ্ন ১৫: SQL Server-এ `CONVERT` Function কী? `CAST` এবং `CONVERT` ফাংশনের মধ্যে মূল পার্থক্য কী?

**উত্তর:**
**`CONVERT`** হলো SQL Server-এর নিজস্ব (Non-ANSI Standard) ডেটাটাইপ কনভার্ট করার ফাংশন। এর মাধ্যমে কাস্টিং করার পাশাপাশি **তারিখ ও সময়ের ফরম্যাটিং (Style)** নির্ধারণ করে দেওয়া যায়।

#### সিনট্যাক্স:
```sql
CONVERT ( target_data_type, expression [, style_number] )
```

#### উদাহরণ (তারিখ ফরম্যাটিং):
```sql
-- DD/MM/YYYY ফরম্যাটে ডেট দেখতে (Style 103):
SELECT CONVERT(VARCHAR(10), GETDATE(), 103); -- আউটপুট: 21/08/2026
```

#### CAST এবং CONVERT এর মূল পার্থক্য:

| বৈশিষ্ট্য | CAST | CONVERT |
| :--- | :--- | :--- |
| **স্ট্যান্ডার্ড** | ANSI SQL স্ট্যান্ডার্ড (সব ডেটাবেসে কাজ করে)। | SQL Server-এর নিজস্ব ফাংশন (MySQL/Oracle-এ সরাসরি কাজ করবে না)। |
| **তারিখের ফরম্যাটিং** | তারিখ বা সময়ের ফরম্যাট স্টাইল সেট করার ক্ষমতা নেই। | ৩য় প্যারামিটার (Style Number) ব্যবহার করে তারিখ ফরম্যাট সেট করা যায়। |

---

### প্রশ্ন ১৬: SQL-এ `COALESCE` Function কী? এটি কীভাবে Non-Null মান খুঁজে বের করে?

**উত্তর:**
**`COALESCE`** ফাংশনটি ব্র্যাকেটের ভেতরের আর্গুমেন্টগুলোর তালিকা থেকে **প্রথম নন-নাল (First Non-Null) মানটি** খুঁজে বের করে রিটার্ন করে। সবগুলো মান যদি `NULL` হয়, তবে এটি শেষ পর্যন্ত `NULL` রিটার্ন করে।

#### সিনট্যাক্স:
```sql
COALESCE ( expression1, expression2, ..., expressionN )
```

#### বাস্তব উদাহরণ:
ধরুন, আমাদের একটি কন্টাক্ট টেবিল আছে যেখানে মেম্বারদের ৩টি যোগাযোগের মাধ্যম আছে (যেমন: OfficePhone, HomePhone, Mobile)। আমরা কাস্টমারকে যেকোনো একটি নম্বরে কল করব, তাই প্রথম যে নম্বরটি সচল (নন-নাল) আছে তা পেতে চাই:

```sql
SELECT Name, COALESCE(Mobile, HomePhone, OfficePhone, 'No Phone Available') AS ContactNumber
FROM MemberContacts;
```
*কাজের মেকানিজম:* যদি Mobile নম্বর থাকে তবে তা দেখাবে। যদি তা Null হয় তবে HomePhone চেক করবে। সেটিও Null হলে OfficePhone দেখাবে। আর সবগুলোই যদি Null হয় তবে 'No Phone Available' দেখাবে।

### প্রশ্ন ১৭: SQL Server-এ `ISNULL` এবং `COALESCE` ফাংশনের মধ্যে মূল পার্থক্য কী?

**উত্তর:**
উভয় ফাংশনের কাজই নাল (`NULL`) ভ্যালু রিপ্লেস করা হলেও এদের মধ্যে কিছু গুরুত্বপূর্ণ পার্থক্য রয়েছে:

#### মূল পার্থক্যসমূহ:

| বৈশিষ্ট্য | ISNULL | COALESCE |
| :--- | :--- | :--- |
| **প্যারামিটারের সংখ্যা** | এটি কেবল ২টি প্যারামিটার নেয় (`ISNULL(val, replacement)`)। | এটি আনলিমিটেড বা একাধিক প্যারামিটার নিতে পারে। |
| **স্ট্যান্ডার্ড** | এটি SQL Server-এর নিজস্ব ফাংশন। | এটি ANSI SQL স্ট্যান্ডার্ড মেনে তৈরি (পোর্টেবল)। |
| **রিটার্ন ডেটাটাইপ** | ১ম প্যারামিটারের ডেটাটাইপ অনুযায়ী রিটার্ন দেয় (যেমন: ১মটি INT হলে ২য়টির টেক্সটও INT-এ রূপান্তর করতে গিয়ে এরর দিতে পারে)। | তালিকার কলামগুলোর মধ্যে সবচেয়ে বেশি প্রায়োরিটি পাওয়া ডেটাটাইপটি রিটার্ন করে। |
| **পারফরম্যান্স** | সামান্য দ্রুত কাজ করে। | ইন্টারনাল প্রসেসিংয়ের কারণে সামান্য ধীর হতে পারে। |
