# Tech Concepts Q&A (স্টাডি নোটস)

এখানে আপনার আলোচনার সব গুরুত্বপূর্ণ টপিকগুলো সহজ প্রশ্ন-উত্তর (Q&A) আকারে সাজিয়ে দেওয়া হলো, যাতে আপনি পরে খুব সহজেই রিভিশন দিতে পারেন।

---

### ডেটাবেস এবং আর্কিটেকচার

**প্রশ্ন ১: ডেটাবেস (Database) কী?**
**উত্তর:** ডেটাবেস হলো ডেটার একটি গোছানো বা অর্নারাইজড সংগ্রহ। এটি এক বা একাধিক সম্পর্কিত ডেটা আইটেম নিয়ে গঠিত হয়, যাদেরকে **রেকর্ড (Records)** বলা হয়। এর মাধ্যমে বিপুল পরিমাণ ডেটা থেকে খুব সহজেই যেকোনো প্রশ্নের (Query) উত্তর খুঁজে বের করা যায়।

**প্রশ্ন ২: DBMS (Database Management System) কী?**
**উত্তর:** 
*   DBMS হলো সম্পর্কিত রেকর্ডগুলোর একটি কালেকশন এবং কিছু প্রোগ্রামের সেট, যা ব্যবহারকারীকে ডেটা এন্টার, স্টোর এবং ম্যানেজ করতে সাহায্য করে।
*   **সহজ পার্থক্য:** ডেটাবেস হলো যেখানে ডেটা থাকে, আর DBMS হলো সেই সফটওয়্যার বা প্রোগ্রাম যা দিয়ে ওই ডেটাগুলো যোগ করা বা মডিফাই করা হয়।
*   **রিয়েল-লাইফ উদাহরণ:** Computerized library systems (যেমন আপনার LibraryMS), ATM (Automated teller machines), বা Flight reservation systems।

**প্রশ্ন ৩: RDBMS (Relational Database Management System) কী?**
**উত্তর:** 
*   RDBMS হলো এমন একটি সফটওয়্যার বা প্রোগ্রাম, যা রিলেশনাল ডেটাবেস তৈরি, পরিচালনা এবং ম্যানিপুলেট করতে সাহায্য করে। এটি ডেটাবেস স্ট্রাকচারকে সহজ করার একটি মডেল।
*   রিলেশনাল ডেটাবেসে ডেটাগুলো ছোট ছোট লজিক্যাল ইউনিটে ভাগ করা থাকে, যাদেরকে **টেবিল (Tables)** বলা হয়। ডেটা মূলত সাধারণ Row (সারি) এবং Column (কলাম) আকারে থাকে।
*   সবচেয়ে বড় সুবিধা হলো, টেবিলগুলো একে অপরের সাথে রিলেটেড (যুক্ত) থাকে। ফলে একটিমাত্র কোয়েরি (Query) চালিয়েই একাধিক টেবিল থেকে প্রয়োজনীয় ডেটা একসাথে তুলে আনা যায়।
*   **উদাহরণ:** SQL Server, MySQL, Oracle ইত্যাদি হলো জনপ্রিয় RDBMS সফটওয়্যার।

**প্রশ্ন ৪: Database Models (ডেটাবেস মডেল) কী এবং এর প্রকারভেদগুলো কী কী?**
**উত্তর:**
ডেটাবেস মডেল মূলত ডেটা কীভাবে স্টোর, সাজানো এবং রিট্রিভ (খুঁজে আনা) হবে তার একটি লজিক্যাল স্ট্রাকচার বা ডিজাইন। প্রধান ৪ ধরনের ডেটাবেস মডেল হলো:
১. **Flat-file Data Model:** এখানে পুরো ডেটাবেসটি একটি মাত্র টেবিল বা ফাইলে থাকে। এটি খুব সিম্পল ডেটার জন্য ব্যবহৃত হয়, তবে এতে ডুপ্লিকেট ডেটা বা Redundancy তৈরি হওয়ার সম্ভাবনা থাকে।
২. **Hierarchical Data Model:** এখানে ডেটাগুলো একটি ট্রি (Tree) বা গাছের মতো স্ট্রাকচারে সাজানো থাকে। একটি প্যারেন্টের (Parent) অনেক চাইল্ড (Child) থাকতে পারে, কিন্তু একটি চাইল্ডের কেবল একটাই প্যারেন্ট থাকে।
৩. **Network Data Model:** এটি হায়ারার্কিকাল মডেলের সমস্যা দূর করার জন্য তৈরি। এখানে একটি চাইল্ডের একাধিক প্যারেন্ট থাকতে পারে, ফলে রেকর্ডগুলো একে অপরের সাথে লিংক করা থাকে।
৪. **Relational Data Model:** আধুনিক SQL ডেটাবেসগুলোতে এটি সবচেয়ে বেশি ব্যবহৃত হয়। এখানে ডেটাগুলোকে টেবিল (সারি এবং কলাম) আকারে রাখা হয় এবং প্রাইমারি/ফরেন-কী এর মাধ্যমে টেবিলগুলোর মধ্যে রিলেশন তৈরি করা হয়।

**প্রশ্ন ৫: Entity, Attribute এবং Entity Set কী? (উদাহরণসহ)**
**উত্তর:**
*   **Entity (এনটিটি):** বাস্তব জগতের যেকোনো ব্যক্তি, বস্তু, স্থান বা ঘটনা, যাকে আলাদাভাবে শনাক্ত করা যায় এবং যার ডেটা আমরা সেভ করতে চাই (যেমন: লাইব্রেরির একজন মেম্বার "রহিম" বা একটি বই "Harry Potter")।
*   **Attribute (অ্যাট্রিবিউট):** একটি এনটিটির বৈশিষ্ট্যগুলো। যেমন "বই" এনটিটির অ্যাট্রিবিউট হলো Title, Author, Price ইত্যাদি। (C#-এ এগুলোকে Properties বলা হয়)।
*   **Entity Set (এনটিটি সেট):** একই রকম অনেকগুলো এনটিটির কালেকশন। যেমন লাইব্রেরির সব বই একসাথে মিলে তৈরি হয় "Books" এনটিটি সেট, যা ডেটাবেসে একটি "Table" (টেবিল) হিসেবে থাকে।

**প্রশ্ন ৬: রিলেশনাল মডেলে Relation, Attribute এবং Tuple বলতে কী বোঝায়?**
**উত্তর:**
রিলেশনাল ডেটাবেস মডেলে (Relational Database Model) আমরা যে টার্মগুলো ব্যবহার করি তার সাথে সাধারণ ডেটাবেস টার্মগুলোর মিল রয়েছে:
*   **Relation (রিলেশন):** ডেটাবেসের ভাষায় একটি **"Table" (টেবিল)** কেই Relation বলা হয়। (যেমন ছবিতে "STUDENT" একটি Relation বা টেবিলের নাম)।
*   **Attribute (অ্যাট্রিবিউট):** টেবিলের **কলামগুলোকে (Columns)** অ্যাট্রিবিউট বলা হয়। এগুলো একটি এনটিটির নির্দিষ্ট বৈশিষ্ট্য প্রকাশ করে। (যেমন ছবিতে Name, Ssn, Age, Gpa ইত্যাদি হলো অ্যাট্রিবিউট)।
*   **Tuple (টাপল):** টেবিলের প্রতিটি **সারি বা রো (Row)** কে Tuple বলা হয়। একটি টাপলে একটি নির্দিষ্ট এনটিটির সম্পূর্ণ ডেটা বা রেকর্ড থাকে। (যেমন ছবিতে "Benjamin Bayer"-এর পুরো রেকর্ডটি একটি Tuple)।

**প্রশ্ন ৭: SQL ডেটাবেসের ফুল লাইফসাইকেল কী?**
**উত্তর:** 
*   **বেসিক লাইফসাইকেল:** রিকোয়ারমেন্ট বোঝা -> ডিজাইন (ER Diagram) -> তৈরি করা (টেবিল/DDL) -> ডেটা ইনসার্ট/আপডেট (DML) -> ডেটা রিট্রিভাল (Select/DQL) -> মেইনটেন্যান্স ও অপ্টিমাইজেশন।
*   **অ্যাডভান্সড/এন্টারপ্রাইজ লাইফসাইকেল:** এর সাথে আরও যুক্ত থাকে ডেটাবেস মাইগ্রেশন (Version Control), লোড টেস্টিং, CI/CD ডিপ্লয়মেন্ট, অডিটিং (কে কী করছে তার লগ রাখা) এবং ডেটা আর্কাইভিং।

**প্রশ্ন ৮: Partitioning এবং Sharding কী?**
**উত্তর:** 
*   **Partitioning:** একটি বিশাল টেবিলকে লজিক্যালি ছোট ছোট ভাগে ভাগ করা (যেমন: সাল অনুযায়ী ডেটা ভাগ করা), যাতে ডেটা দ্রুত খোঁজা যায়। এটি একই সার্ভারের ভেতরেই করা হয়।
*   **Sharding:** ডেটাকে একাধিক আলাদা ফিজিক্যাল সার্ভারে ভাগ করে রাখা। যেমন: এশিয়ার ইউজারদের ডেটা সার্ভার-১ এ এবং ইউরোপের ইউজারদের ডেটা সার্ভার-২ এ রাখা।

### SQL বেসিক কমান্ডস এবং ভোকাবুলারি

**প্রশ্ন ৯: SQL-এ Statement, Clause, Operator and Function বলতে কী বোঝায়?**
**উত্তর:**
SQL-এর পরিভাষাগুলো (Vocabulary) পরিষ্কারভাবে বুঝতে হলে নিচের ভাগগুলো জানা জরুরি:
১. **Statement / Command (স্টেটমেন্ট বা কমান্ড):** ডেটাবেসকে দেওয়া একটি সম্পূর্ণ নির্দেশ। যেমন: `SELECT`, `INSERT`, `UPDATE`, `CREATE` ইত্যাদি এক একটি সম্পূর্ণ স্টেটমেন্ট।
২. **Clause (ক্লজ):** এটি একটি statement-এর অংশ, যা ডেটাকে ফিল্টার বা সাজাতে সাহায্য করে। যেমন: `WHERE` (শর্ত দেওয়ার জন্য), `ORDER BY` (সাজানোর জন্য), `GROUP BY` (গ্রুপ করার জন্য)।
৩. **Operator (অপারেটর):** বিভিন্ন লজিক বা গাণিতিক শর্ত দেওয়ার জন্য যেসব কিওয়ার্ড বা চিহ্ন ব্যবহৃত হয়। 
   * *লজিক্যাল:* `AND`, `OR`, `NOT`
   * *তুলনামূলক:* `=`, `>`, `<`, `LIKE`, `IN`, `BETWEEN`
৪. **Function (ফাংশন):** SQL-এর ভেতরে থাকা রেডিমেড টুলস যা হিসাব-নিকাশ করে। যেমন: `COUNT()` (কয়টি ডেটা আছে গুণতে), `SUM()` (যোগফল বের করতে), `MAX()` (বড় সংখ্যা বের করতে)।

**প্রশ্ন ১০: SQL-এ Database/Table তৈরি, ডেটা ইনসার্ট, আপডেট এবং ডিলিট করার বেসিক সিনট্যাক্সগুলো কী কী?**
**উত্তর:**
নিচে সবচেয়ে বেশি ব্যবহৃত SQL কমান্ডগুলোর সিনট্যাক্স দেওয়া হলো:

১. **ডেটাবেস তৈরি (Create Database):**
```sql
CREATE DATABASE DatabaseName;
```
২. **ডেটাবেস মুছে ফেলা (Drop Database):**
```sql
DROP DATABASE DatabaseName;
```
৩. **টেবিল তৈরি (Create Table):**
```sql
CREATE TABLE TableName (
    Column1 DataType, 
    Column2 DataType
);
```
৪. **টেবিলে ডেটা ঢোকানো (Insert Data):**
```sql
INSERT INTO TableName (Column1, Column2) 
VALUES (Value1, Value2);
```
৫. **ডেটা আপডেট বা পরিবর্তন করা (Update Data):**
```sql
UPDATE TableName SET Column1 = Value1 WHERE Condition;
```
৬. **ডেটা মুছে ফেলা (Delete Data):**
```sql
DELETE FROM TableName WHERE Condition;
```
৭. **টেবিল খালি করা (Truncate Table):**
```sql
TRUNCATE TABLE TableName;
```

**প্রশ্ন ১১: SELECT Statement, ORDER BY Clause, LIKE Operator এবং Name Change করার সিনট্যাক্স কী?**
**উত্তর:**
১. **SELECT Statement (ডেটা তুলে আনা):**
```sql
SELECT * FROM Students;
```
২. **ORDER BY Clause (ডেটা সাজানো):**
```sql
SELECT * FROM Students ORDER BY Age DESC; 
```
৩. **LIKE Operator (প্যাটার্ন খোঁজা):**
```sql
SELECT * FROM Students WHERE Name LIKE 'A%';
```
৪. **Database এবং Table এর নাম পরিবর্তন (Rename):**
```sql
ALTER DATABASE OldDatabaseName MODIFY NAME = NewDatabaseName;
EXEC sp_rename 'OldTableName', 'NewTableName';
```

**প্রশ্ন ১২: SQL-এ BETWEEN, TOP (PERCENT), DISTINCT, IN, এবং NOT IN এর কাজ কী? (উদাহরণসহ)**
**উত্তর:**

১. **BETWEEN Operator (রেঞ্জ খোঁজা):**
দুটি নির্দিষ্ট মানের (Value) মাঝখানের ডেটা খুঁজে বের করতে এটি ব্যবহার করা হয় (যেমন: নির্দিষ্ট প্রাইস রেঞ্জ বা তারিখের রেঞ্জ)।
```sql
-- যাদের বয়স ২০ থেকে ৩০ এর মধ্যে তাদের ডেটা দেখাবে:
SELECT * FROM Students WHERE Age BETWEEN 20 AND 30;
```

২. **TOP Clause (নির্দিষ্ট সংখ্যক ডেটা আনা):**
পুরো টেবিল না এনে, শুধুমাত্র ওপরের কয়েকটি ডেটা আনতে এটি ব্যবহৃত হয় (বিশেষ করে SQL Server-এ)। 
```sql
-- টেবিলের প্রথম ১০ জনের ডেটা দেখাবে:
SELECT TOP 10 * FROM Students;
```

৩. **TOP ... PERCENT (শতকরা হিসেবে ডেটা আনা):**
ডেটার নির্দিষ্ট কোনো পরিমাণ না দিয়ে, পার্সেন্টেজ হিসেবে ডেটা আনতে এটি ব্যবহৃত হয়।
```sql
-- টেবিলের মোট ডেটার অর্ধেক (৫০%) দেখাবে:
SELECT TOP 50 PERCENT * FROM Students;
```

৪. **DISTINCT Clause (ডুপ্লিকেট ডেটা বাদ দেওয়া):**
টেবিলে যদি একই ডেটা বারবার থাকে (যেমন অনেকেই ঢাকা থেকে এসেছে), তবে DISTINCT ব্যবহার করলে প্রতিটি ডেটা মাত্র একবার করে দেখাবে (Unique values)।
```sql
-- কোন কোন শহর থেকে স্টুডেন্টরা এসেছে (শুধু ইউনিক শহরের নামগুলো):
SELECT DISTINCT City FROM Students;
```

৫. **IN Operator (একাধিক অপশন থেকে খোঁজা):**
WHERE ক্লজে বারবার `OR` ব্যবহার না করে, একটি লিস্টের মধ্যে মানগুলো দিয়ে দিতে এটি ব্যবহৃত হয়।
```sql
-- যাদের শহর ঢাকা, সিলেট অথবা খুলনা তাদের ডেটা দেখাবে:
SELECT * FROM Students WHERE City IN ('Dhaka', 'Sylhet', 'Khulna');
```

৬. **NOT IN Operator (বাদ দিয়ে খোঁজা):**
যে মানগুলো লিস্টে দেওয়া হবে, শুধু সেগুলো বাদ দিয়ে বাকি সব ডেটা দেখাবে।
```sql
-- ঢাকা এবং চট্টগ্রামের স্টুডেন্ট বাদে বাকি সবার ডেটা দেখাবে:
SELECT * FROM Students WHERE City NOT IN ('Dhaka', 'Chittagong');
```

**প্রশ্ন ১৩: SQL-এ Constraints (কনস্ট্রেইন্ট) কী? NOT NULL, UNIQUE, PRIMARY KEY, CHECK এবং DEFAULT এর কাজ কী?**
**উত্তর:**
**Constraints (কনস্ট্রেইন্ট)** মানে হলো কিছু নির্দিষ্ট নিয়ম বা শর্ত (Rules), যা টেবিলের কলামের ওপর বসানো হয়। এটি ডেটাবেসে ভুল বা অবৈধ ডেটা ঢোকা বন্ধ করে এবং ডেটার কোয়ালিটি ঠিক রাখে।

সবচেয়ে ব্যবহৃত ৫টি কনস্ট্রেইন্ট হলো:

১. **NOT NULL:**
    এই কনস্ট্রেইন্ট থাকলে ওই কলামটি ফাঁকা (Null) রাখা যাবে না। ডেটা ইনসার্ট করার সময় অবশ্যই কোনো না কোনো ভ্যালু দিতে হবে।
*(উদাহরণ: ইউজারের নাম বা ইমেইল কখনো ফাঁকা হতে পারবে না।)*

২. **UNIQUE:**
    এই কনস্ট্রেইন্ট নিশ্চিত করে যে, কলামের প্রতিটি ডেটা সবার থেকে আলাদা হবে। অর্থাৎ, কোনো ডুপ্লিকেট ডেটা রাখা যাবে না।
*(উদাহরণ: একাধিক ইউজারের ইমেইল অ্যাড্রেস বা ফোন নাম্বার কখনো এক হতে পারবে না।)*

৩. **PRIMARY KEY:**
    এটি `NOT NULL` and `UNIQUE` উভয়ের একটি মিশ্রণ। এটি টেবিলের প্রতিটি রো (Row) বা রেকর্ডকে আলাদাভাবে (Uniquely) শনাক্ত করতে সাহায্য করে। মনে রাখবেন, একটি টেবিলে কেবল একটিই প্রাইমারি কী থাকতে পারে।
*(উদাহরণ: StudentId, UserID বা NID Number।)*

৪. **CHECK:**
    এই কনস্ট্রেইন্ট দিয়ে একটি শর্ত নির্দিষ্ট করে দেওয়া যায়। কেবল সেই শর্ত পূরণ হলেই ডেটা টেবিলে সেভ হবে, নাহলে এরর দেবে।
*(উদাহরণ: বয়স ১৮ এর নিচে হওয়া যাবে না- `CHECK (Age >= 18)`)*

৫. **DEFAULT:**
    ডেটা ইনসার্ট করার সময় যদি ইউজার কোনো কলামের মান না দেয়, তবে এই কনস্ট্রেইন্টটি একটি ডিফল্ট বা ফিক্সড মান নিজে থেকেই বসিয়ে দেয়।
*(উদাহরণ: Country কলামে ডিফল্টভাবে 'Bangladesh' সেট করে রাখা, যাতে কেউ দেশের নাম না দিলে অটোমেটিক বাংলাদেশ বসে যায়- `DEFAULT 'Bangladesh'`)*

**প্রশ্ন ১৪: SQL-এ ALTER Command, IDENTITY (Auto Increment) এবং ALIAS এর কাজ কী? (সিনট্যাক্সসহ)**
**উত্তর:**

১. **ALTER Command (টেবিলের স্ট্রাকচার পরিবর্তন):**
    একবার টেবিল তৈরি হয়ে যাওয়ার পর, সেই টেবিলে নতুন কোনো কলাম যোগ করা, কলাম মুছে ফেলা বা কলামের ডেটাটাইপ পরিবর্তন করার জন্য `ALTER TABLE` কমান্ড ব্যবহৃত হয়।
```sql
-- ১. টেবিলে নতুন কলাম যোগ করা:
ALTER TABLE Students ADD Email VARCHAR(255);

-- ২. টেবিল থেকে কোনো কলাম মুছে ফেলা:
ALTER TABLE Students DROP COLUMN Email;

-- ৩. কলামের ডেটাটাইপ পরিবর্তন করা (SQL Server):
ALTER TABLE Students ALTER COLUMN Age INT; 
```

২. **IDENTITY / Auto Increment (স্বয়ংক্রিয় নম্বর জেনারেট):**
    ডেটাবেসে যখন আমরা নতুন কোনো রেকর্ড ইনসার্ট করি, তখন প্রাইমারি কী (Primary Key) এর জন্য বারবার নিজে থেকে আইডি (যেমন: 1, 2, 3...) না লিখে, ডেটাবেসকে দায়িত্ব দেওয়া হয় স্বয়ংক্রিয়ভাবে একটির পর একটি নম্বর বসানোর জন্য। 
*   SQL Server-এ একে **IDENTITY** বলা হয়।
*   MySQL-এ একে **AUTO_INCREMENT** বলা হয়।
```sql
-- SQL Server-এ IDENTITY(শুরু হবে ১ থেকে, বাড়বে ১ করে):
CREATE TABLE Students (
    StudentID INT IDENTITY(1,1) PRIMARY KEY,
    Name VARCHAR(50)
);
-- এখন ডেটা ইনসার্ট করার সময় StudentID দিতে হবে না। 
```

৩. **ALIAS (ছদ্মনাম দেওয়া):**
    টেবিল বা কলামের আসল নাম পরিবর্তন না করে, শুধুমাত্র রেজাল্ট দেখার সুবিধার জন্য বা কোয়েরি ছোট করার জন্য সাময়িকভাবে (Temporary) একটি ছদ্মনাম দেওয়াকে ALIAS বলা হয়। এটি `AS` কিওয়ার্ড দিয়ে করা হয়।
```sql
-- কলামের নাম Alias করা (রেজাল্টে Name এর বদলে Student Name দেখাবে):
SELECT Name AS 'Student Name', Age FROM Students;

-- টেবিলের নাম Alias করা (JOIN করার সময় এটি কোয়েরিকে ছোট ও সুন্দর করে):
SELECT s.Name FROM Students AS s WHERE s.Age > 20;
```

**প্রশ্ন ১৫: SQL-এ Primary Key এবং Foreign Key বলতে কী বোঝায়?**
**উত্তর:**
রিলেশনাল ডেটাবেসে ডেটার পরিচিতি এবং টেবিলের সাথে টেবিলের সম্পর্ক (Relationship) তৈরি করার জন্য এই কী (Key) গুলো ব্যবহার করা হয়।

১. **Primary Key (প্রাইমারি কী):**
    প্রাইমারি কী হলো টেবিলের এমন একটি কলাম, যা টেবিলের প্রতিটি রেকর্ডকে অদ্বিতীয়ভাবে (Uniquely) শনাক্ত করে।
*   **নিয়ম:** এটি অবশ্যই `NOT NULL` (ফাঁকা রাখা যাবে না) এবং `UNIQUE` (ডুপ্লিকেট রাখা যাবে না) হতে হবে। একটি টেবিলে কেবল **একটিই** প্রাইমারি কী থাকতে পারে।
*   **উদাহরণ:** মানুষের NID নাম্বার বা স্টুডেন্টদের `StudentID`।

২. **Foreign Key (ফরেন কী):**
    ফরেন কী হলো একটি টেবিলের এমন একটি কলাম, যা অন্য একটি টেবিলের "প্রাইমারি কী" কে নির্দেশ করে (Reference করে)। এটি দুটি টেবিলের মধ্যে সম্পর্ক (Relationship) তৈরি করতে ব্যবহৃত হয়।
*   **নিয়ম:** ফরেন কী-এর মাধ্যমে ডেটার অখণ্ডতা (Referential Integrity) বজায় থাকে, অর্থাৎ অন্য টেবিলে নেই এমন কোনো ডেটা ইনসার্ট করা যায় না। একটি টেবিলে একাধিক ফরেন কী থাকতে পারে এবং এতে ডুপ্লিকেট বা Null ভ্যালুও থাকতে পারে (যদি নট নাল সেট করা না হয়)।
*   **উদাহরণ:** `Students` টেবিলে যদি একটি `DepartmentID` কলাম থাকে যা `Departments` টেবিলের `DepartmentID` (প্রাইমারি কী) কে নির্দেশ করে, তাহলে `Students` টেবিলের `DepartmentID` হলো ফরেন কী।

**প্রশ্ন ১৬: SQL-এ Composite Key বা Composite Primary Key কী? কীভাবে তৈরি করতে হয়?**
**উত্তর:**
কখনো কখনো এমন হয় যে, টেবিলের একটি মাত্র কলাম দিয়ে কোনো রেকর্ডকে অদ্বিতীয়ভাবে (Uniquely) শনাক্ত করা সম্ভব হয় না। তখন **একাধিক কলাম মিলিয়ে একটি প্রাইমারি কী তৈরি করা হয়**। এই একাধিক কলামের মিলিত রূপকেই **Composite Key** বা **Composite Primary Key** বলা হয়।

*   **কেন লাগে:** ধরুন একটি `Enrollments` টেবিলে স্টুডেন্টরা কোর্সে ভর্তি হয়। এখানে শুধু `StudentID` ইউনিক নয় (কারণ এক স্টুডেন্ট অনেক কোর্স নিতে পারে), আবার শুধু `CourseID` ইউনিক নয় (কারণ এক কোর্সে অনেক স্টুডেন্ট থাকতে পারে)। কিন্তু `StudentID` এবং CourseID দুটি মিলিয়ে সবসময় ইউনিক হবে (কারণ এক স্টুডেন্ট একই কোর্সে দু'বার ভর্তি হতে পারবে না)।

*   **সিনট্যাক্স:**
```sql
CREATE TABLE Enrollments (
    StudentID INT,
    CourseID INT,
    EnrollmentDate DATE,
    -- একাধিক কলাম মিলিয়ে একটি Primary Key তৈরি করা হলো:
    PRIMARY KEY (StudentID, CourseID) 
);
```

**প্রশ্ন ১৭: ALTER কমান্ড ব্যবহার করে কীভাবে SQL-এ Constraints (কনস্ট্রেইন্ট) Add এবং Drop করতে হয়?**
**উত্তর:**
অনেক সময় টেবিল তৈরি করার পর মনে পড়ে যে কোনো কলামে Primary Key বা Unique কনস্ট্রেইন্ট দেওয়া হয়নি। তখন টেবিল ডিলিট না করে `ALTER TABLE` ব্যবহার করে সহজেই কনস্ট্রেইন্ট যোগ (Add) বা মুছে (Drop) ফেলা যায়।

**১. Primary Key অ্যাড এবং ড্রপ করা:**
```sql
-- Add (যোগ করা):
ALTER TABLE Students ADD CONSTRAINT PK_Student PRIMARY KEY (StudentID);

-- Drop (মুছে ফেলা):
ALTER TABLE Students DROP CONSTRAINT PK_Student;
```

**২. Foreign Key অ্যাড এবং ড্রপ করা:**
```sql
-- Add (যোগ করা):
ALTER TABLE Students ADD CONSTRAINT FK_Department 
FOREIGN KEY (DepartmentID) REFERENCES Departments(DepartmentID);

-- Drop (মুছে ফেলা):
ALTER TABLE Students DROP CONSTRAINT FK_Department;
```

**৩. UNIQUE বা CHECK কনস্ট্রেইন্ট অ্যাড এবং ড্রপ করা:**
```sql
-- Add (যোগ করা):
ALTER TABLE Students ADD CONSTRAINT UQ_Email UNIQUE (Email);
ALTER TABLE Students ADD CONSTRAINT CHK_Age CHECK (Age >= 18);

-- Drop (মুছে ফেলা):
ALTER TABLE Students DROP CONSTRAINT UQ_Email;
```
*(নোট: কনস্ট্রেইন্টের নাম (যেমন `PK_Student`, `UQ_Email`) নিজে থেকে একটি মিনিংফুল নাম দেওয়াই ভালো, যাতে পরে ড্রপ করতে সুবিধা হয়।)*

**প্রশ্ন ১৮: Cascading Referential Integrity Constraint বা Cascading Foreign Key বলতে কী বোঝায়?**
**উত্তর:**
আমরা জানি Foreign Key দিয়ে দুটি টেবিলের (যেমন Parent এবং Child টেবিল) মধ্যে সম্পর্ক তৈরি করা হয়। এখন যদি Parent টেবিল থেকে কোনো রেকর্ড ডিলিট করা হয় বা প্রাইমারি কী আপডেট করা হয়, তখন Child টেবিলে থাকা যুক্ত রেকর্ডগুলোর কী হবে? সেটি নির্ধারণ করে দেওয়াই হলো **Cascading Referential Integrity Constraint**।

এর মূলত ৪টি অ্যাকশন বা রুল আছে:

১. **NO ACTION (ডিফল্ট):** 
    এটি ডিফল্ট আচরণ। যদি Parent টেবিলের কোনো ডেটা ডিলিট করার চেষ্টা করা হয় এবং Child টেবিলে সেটির কোনো ডেটা থাকে, তবে ডেটাবেস এরর দেবে এবং ডিলিট করতে দেবে না।

২. **CASCADE (ক্যাসকেড):** 
    সবচেয়ে বেশি ব্যবহৃত অপশন। 
*   `ON DELETE CASCADE:` Parent টেবিল থেকে কোনো রেকর্ড ডিলিট করলে, Child টেবিলে থাকা তার সাথে সম্পর্কিত সব রেকর্ড **অটোমেটিক ডিলিট** হয়ে যাবে।
*   `ON UPDATE CASCADE:` Parent টেবিলের প্রাইমারি কী আপডেট করলে, Child টেবিলে থাকা ফরেন কী-এর মানও **অটোমেটিক আপডেট** হয়ে যাবে।

৩. **SET NULL:** 
    Parent টেবিল থেকে রেকর্ড ডিলিট বা আপডেট করলে, Child টেবিলে থাকা ফরেন কী-এর মান অটোমেটিক `NULL` হয়ে যাবে (তবে কলামটিকে Nullable হতে হবে)।

৪. **SET DEFAULT:** 
    Parent টেবিল থেকে রেকর্ড ডিলিট বা আপডেট করলে, Child টেবিলে ফরেন কী-এর মান পরিবর্তন হয়ে আগে থেকে সেট করে রাখা Default ভ্যালুতে চলে যাবে।

**সিনট্যাক্স (CASCADE উদাহরণ):**
```sql
CREATE TABLE Employees (
    EmpID INT PRIMARY KEY,
    Name VARCHAR(50),
    DeptID INT,
    -- Foreign Key ডিক্লেয়ারেশন এবং Cascading রুলস:
    FOREIGN KEY (DeptID) REFERENCES Departments(DeptID) 
    ON DELETE CASCADE 
    ON UPDATE CASCADE
);
```

**প্রশ্ন ১৯: SQL-এ UNION, UNION ALL, INTERSECT এবং EXCEPT কী? এগুলো কি অপারেটর?**
**উত্তর:**
হ্যাঁ, এগুলো হলো SQL-এর **Set Operators (সেট অপারেটর)**। এদের কাজ হলো দুটি বা তার বেশি `SELECT` কোয়েরির রেজাল্টকে একসাথে মিলিয়ে একটিমাত্র রেজাল্ট তৈরি করা। 

এই অপারেটরগুলো ব্যবহার করার প্রধান শর্ত হলো: সবগুলো `SELECT` কোয়েরিতে কলাম সংখ্যা এবং কলামের ডেটাটাইপ (Data Type) একই হতে হবে।

১. **UNION:**
    এটি দুটি কোয়েরির রেজাল্টকে যোগ করে, কিন্তু ডুপ্লিকেট (Duplicate) রেকর্ডগুলো বাদ দিয়ে দেয়। শুধুমাত্র ইউনিক ভ্যালু দেখায়।
```sql
SELECT City FROM Customers
UNION
SELECT City FROM Suppliers;
```

২. **UNION ALL:**
    এটিও দুটি কোয়েরির রেজাল্ট যোগ করে, কিন্তু এটি কোনো ডুপ্লিকেট ভ্যালু বাদ দেয় না। সবগুলো ডেটাই দেখায়। (যেহেতু এটি ডুপ্লিকেট চেক করে না, তাই এটি `UNION` এর চেয়ে ফাস্ট কাজ করে)।
```sql
SELECT City FROM Customers
UNION ALL
SELECT City FROM Suppliers;
```

৩. **INTERSECT:**
    এটি দুটি কোয়েরির রেজাল্টের মধ্যে শুধুমাত্র **কমন (Common)** ডেটাগুলো দেখায়। অর্থাৎ, যে ডেটাটি দুটি টেবিলের রেজাল্টেই আছে, শুধু সেটিই আউটপুটে আসবে।
```sql
SELECT City FROM Customers
INTERSECT
SELECT City FROM Suppliers;
```

৪. **EXCEPT (Oracle এ MINUS):**
    এটি প্রথম কোয়েরির রেজাল্ট থেকে দ্বিতীয় কোয়েরির রেজাল্ট **বাদ (Subtract)** দিয়ে দেয়। অর্থাৎ প্রথম টেবিলে আছে কিন্তু দ্বিতীয় টেবিলে নেই, এমন ডেটাগুলোই শুধু দেখাবে।
```sql
SELECT City FROM Customers
EXCEPT
SELECT City FROM Suppliers;
```

**প্রশ্ন ২০: SQL-এ Aggregate Functions (SUM, MAX, MIN, COUNT, AVG) and GROUP BY এর কাজ কী? (উদাহরণসহ)**
**উত্তর:**
**Aggregate Functions** হলো এমন কিছু বিল্ট-ইন ফাংশন যা ডেটাবেসের একাধিক ডেটা বা রো (Row) এর ওপর ক্যালকুলেশন করে একটিমাত্র রেজাল্ট (Single Value) রিটার্ন করে। এগুলো সাধারণত `GROUP BY` ক্লজের সাথে মিলিয়ে ব্যবহৃত হয়।

**প্রধান ৫টি Aggregate Function:**
১. **COUNT():** একটি কলামে মোট কয়টি ডেটা (Row) আছে তা গোনে।
২. **SUM():** একটি কলামের সবগুলো সংখ্যার যোগফল বের করে (শুধু Number ডেটার ওপর কাজ করে)।
৩. **AVG():** সবগুলো সংখ্যার গড় (Average) বের করে।
４. **MAX():** কলামের মধ্যে সবচেয়ে বড় সংখ্যা বা মানটি খুঁজে বের করে।
৫. **MIN():** কলামের মধ্যে সবচেয়ে ছোট সংখ্যা বা মানটি খুঁজে বের করে।

**GROUP BY ক্লজ কী?**
যখন আমরা একই ধরনের ডেটাকে গ্রুপ করে তাদের ওপর কোনো Aggregate Function চালাতে চাই, তখন `GROUP BY` ব্যবহার করা হয়। যেমন: "প্রতিটি ডিপার্টমেন্টে মোট কতজন এমপ্লয়ি আছে?" - এখানে "ডিপার্টমেন্ট" ধরে গ্রুপ করতে হবে।

**সিনট্যাক্স ও উদাহরণ:**

```sql
-- ১. COUNT (মোট কতজন স্টুডেন্ট আছে?):
SELECT COUNT(StudentID) FROM Students;

-- ২. MAX এবং MIN (সবচেয়ে বেশি এবং কম বয়স কত?):
SELECT MAX(Age) AS MaxAge, MIN(Age) AS MinAge FROM Students;

-- ৩. SUM এবং AVG (সব এমপ্লয়ির মোট স্যালারি এবং গড় স্যালারি কত?):
SELECT SUM(Salary) AS TotalSalary, AVG(Salary) AS AverageSalary FROM Employees;

-- ৪. GROUP BY (প্রতিটি ডিপার্টমেন্টে মোট কত স্যালারি দেওয়া হয়?):
SELECT Department, SUM(Salary) AS TotalDeptSalary
FROM Employees
GROUP BY Department;
```

**প্রশ্ন ২১: SQL-এ HAVING এবং WHERE ক্লজের মধ্যে মূল পার্থক্য কী? (HAVING vs WHERE)**
**উত্তর:**
`WHERE` এবং `HAVING` উভয়ের কাজই হলো ডেটা ফিল্টার করা (শর্ত দেওয়া)। কিন্তু এদের ব্যবহারের জায়গা এবং কাজের ধরনে একটি বড় পার্থক্য আছে।

**মূল পার্থক্য:**
১. **ব্যবহারের স্থান:**
   * **WHERE:** টেবিলের প্রতিটি সিঙ্গেল ডেটা বা রো (Row)-এর ওপর ফিল্টার করতে ব্যবহৃত হয়। এটি `GROUP BY` ক্লজের **আগে** বসে।
   * **HAVING:** ডেটাকে গ্রুপ করার পর, সেই গ্রুপের ওপর ফিল্টার করতে ব্যবহৃত হয়। এটি `GROUP BY` ক্লজের **পরে** বসে।

২. **Aggregate Function (SUM, COUNT ইত্যাদি) এর সাথে ব্যবহার:**
   * **WHERE:** `WHERE` ক্লজের ভেতরে কখনোই Aggregate Function (যেমন: COUNT, SUM) ব্যবহার করা যায় না।
   * **HAVING:** `HAVING` ক্লজ মূলত তৈরিই করা হয়েছে Aggregate Function-এর সাথে শর্ত ব্যবহার করার জন্য। 

**একসাথে ব্যবহারের চমৎকার উদাহরণ:**
ধরুন, আমরা দেখতে চাই কোন কোন ডিপার্টমেন্টে ৫ জনের বেশি এমপ্লয়ি আছে, কিন্তু আমরা শুধু সেইসব এমপ্লয়িদেরই হিসাব করব যাদের বয়স ২০ বছরের বেশি।

```sql
SELECT Department, COUNT(EmpID) AS NumberOfEmployees
FROM Employees
-- ১. WHERE: প্রথমে যাদের বয়স ২০-এর বেশি, শুধু তাদের ফিল্টার করা হলো (Row লেভেলে)
WHERE Age > 20 
-- ২. GROUP BY: এরপর তাদেরকে ডিপার্টমেন্ট অনুযায়ী গ্রুপ করা হলো
GROUP BY Department
-- ৩. HAVING: সবশেষে গ্রুপের ওপর শর্ত দেওয়া হলো (যেখানে এমপ্লয়ি সংখ্যা ৫-এর বেশি)
HAVING COUNT(EmpID) > 5;
```

**প্রশ্ন ২২: SQL-এ ROLLUP এবং CUBE এর কাজ কী? (GROUP BY এর অ্যাডভান্সড ব্যবহার)**
**উত্তর:**
`ROLLUP` এবং `CUBE` হলো `GROUP BY` ক্লজের দুটি অ্যাডভান্সড এক্সটেনশন। এগুলো মূলত ডেটাবেসে রিপোর্টিং (Reporting) করার সময় **Subtotal** এবং **Grand Total** বের করার জন্য ব্যবহৃত হয়।

১. **ROLLUP:**
    `ROLLUP` ব্যবহার করলে এটি হায়ারার্কি (Hierarchical) অনুযায়ী Subtotal তৈরি করে এবং সবশেষে একটি গ্র্যান্ড টোটাল (Grand Total) দেখায়। এটি ডানদিক থেকে বাঁদিকে কলামগুলোর টোটাল হিসাব করে।
*   **উদাহরণ:** আপনি যদি Country এবং City অনুযায়ী সেলস দেখতে চান, তবে `ROLLUP` প্রথমে প্রতিটি City-এর সেলস দেখাবে, তারপর প্রতিটি Country-এর Subtotal দেখাবে এবং শেষে সবার মোট Grand Total দেখাবে।
*   **সিনট্যাক্স:**
```sql
SELECT Country, City, SUM(SalesAmount) AS TotalSales
FROM Sales
GROUP BY ROLLUP (Country, City);
```

২. **CUBE:**
    `CUBE` হলো `ROLLUP` এর চেয়েও আরও একধাপ অ্যাডভান্সড। এটি কলামগুলোর **সম্ভাব্য সব ধরনের কম্বিনেশনের (Combinations)** জন্য Subtotal তৈরি করে এবং শেষে একটি Grand Total দেখায়।
*   **উদাহরণ:** ওপরের উদাহরণে `CUBE` ব্যবহার করলে এটি City-এর জন্য Subtotal দেখাবে, Country-এর জন্য Subtotal দেখাবে, শুধু City-এর টোটাল দেখাবে, শুধু Country-এর টোটাল দেখাবে, অর্থাৎ সব অ্যাঙ্গেল থেকে টোটাল দেখাবে।
*   **সিনট্যাক্স:**
```sql
SELECT Country, City, SUM(SalesAmount) AS TotalSales
FROM Sales
GROUP BY CUBE (Country, City);
```

**সহজ পার্থক্য:** 
`ROLLUP` শুধু একটি নির্দিষ্ট অর্ডারে (যেমন Country -> City) সাবটোটাল দেয়। আর `CUBE` সবদিকে ক্রস-হিসাব করে সম্ভাব্য সব সাবটোটাল দিয়ে দেয়।

**প্রশ্ন ২৩: SQL-এ GROUPING SETS কী এবং কেন ব্যবহার করা হয়?**
**উত্তর:**
`GROUPING SETS` হলো `GROUP BY` ক্লজের আরেকটি চমৎকার এক্সটেনশন (যেমনটি ROLLUP বা CUBE)। 

**কেন ব্যবহার করা হয়?**
অনেক সময় `CUBE` ব্যবহার করলে এমন অনেক সাবটোটাল জেনারেট হয়ে যায়, যা আমাদের দরকার নেই (ফলে পারফরম্যান্স স্লো হয়)। আবার `ROLLUP` ব্যবহার করলে সেটি একটি নির্দিষ্ট অর্ডারে টোটাল দেখায়, যা হয়তো আমাদের মনের মতো হয় না। 

এসব ক্ষেত্রে `GROUPING SETS` ব্যবহার করা হয়। এর মাধ্যমে আমরা **একেবারে সুনির্দিষ্টভাবে বলে দিতে পারি** যে, ঠিক কোন কোন কলামের ওপর বা কোন কোন গ্রুপের সাবটোটাল বা গ্র্যান্ড টোটাল আমরা চাচ্ছি। 

**উদাহরণ ও সিনট্যাক্স:**
ধরুন, আমরা Country এবং City এর সেলস রিপোর্ট চাই, কিন্তু আমরা শুধুমাত্র "দুটো মিলিয়ে একটি টোটাল", "শুধুমাত্র Country অনুযায়ী টোটাল", এবং একটি "Grand Total" চাই। `CUBE` ব্যবহার করলে খামাখা City এর আলাদাও টোটাল চলে আসতো, কিন্তু `GROUPING SETS` দিয়ে আমরা ঠিক যা চাই তাই নিতে পারি:

```sql
SELECT Country, City, SUM(SalesAmount) AS TotalSales
FROM Sales
GROUP BY GROUPING SETS (
    (Country, City),  -- ১. Country এবং City মিলিয়ে সাধারণ Group By
    (Country),        -- ২. শুধু Country অনুযায়ী Subtotal
    ()                -- ৩. সবার শেষের Grand Total (ফাঁকা ব্র্যাকেট দিয়ে বোঝায়)
);
```
*নোট: একাধিক `GROUP BY` কোয়েরি লিখে সেগুলোকে `UNION ALL` দিয়ে জোড়া লাগানোর চেয়ে একটি `GROUPING SETS` লেখা অনেক বেশি ফাস্ট এবং ক্লিন।*

**প্রশ্ন ২৪: SQL-এ Stored Procedure কী এবং কেন ব্যবহার করা হয়?**
**উত্তর:**
**Stored Procedure (স্টোরড প্রসিডিউর)** হলো SQL কোড বা কোয়েরির একটি ব্লক, যা ডেটাবেসে সেভ (Save) করে রাখা যায় এবং পরবর্তীতে বারবার ব্যবহার (Reuse) করা যায়। 

এটিকে আপনি C# বা যেকোনো প্রোগ্রামিং ল্যাঙ্গুয়েজের **Function (ফাংশন) বা মেথড** এর সাথে তুলনা করতে পারেন। আপনি একবার লজিক লিখে ডেটাবেসে সেভ করে রাখবেন, আর যখনই দরকার হবে শুধু এর নাম ধরে কল করবেন (Parameter বা ভ্যালু পাস করে)।

**কেন ব্যবহার করা হয়? (সুবিধা):**
১. **Reusability (পুনর্ব্যবহারযোগ্য):** একই SQL কোড বারবার লিখতে হয় না। একবার বানিয়ে বারবার কল করা যায়।
২. **Performance (দ্রুতগতি):** প্রথমবার রান করার সময় SQL Server একে কম্পাইল করে Execution Plan সেভ করে রাখে (ক্যাশিং)। ফলে বারবার কল করলে এটি সাধারণ SQL কোয়েরির চেয়ে অনেক দ্রুত রান করে।
৩. **Security (নিরাপত্তা):** এটি SQL Injection এর মতো সাইবার অ্যাটাক থেকে ডেটাবেসকে রক্ষা করে। এছাড়া, ইউজারদের সরাসরি টেবিলে অ্যাক্সেস না দিয়ে, শুধু Procedure রান করার পারমিশন দেওয়া যায়।
৪. **Network Traffic কমায়:** ক্লায়েন্ট অ্যাপ্লিকেশন থেকে হাজার লাইনের SQL কোয়েরি নেটওয়ার্ক দিয়ে পাঠানোর বদলে, শুধু Procedure এর নামটি পাঠালেই হয়।

**সিনট্যাক্স ও উদাহরণ:**
ধরুন, আপনি নির্দিষ্ট কোনো সিটির স্টুডেন্টদের ডেটা দেখতে চান। এর জন্য একটি Stored Procedure বানানো হলো:

```sql
-- ১. Stored Procedure তৈরি করা (Create):
CREATE PROCEDURE GetStudentsByCity
    @CityName VARCHAR(50)  -- এটি একটি প্যারামিটার (C# এর মেথড প্যারামিটারের মতো)
AS
BEGIN
    SELECT * FROM Students WHERE City = @CityName;
END;
```

```sql
-- ২. Stored Procedure ব্যবহার করা বা চালানো (Execute):
EXEC GetStudentsByCity @CityName = 'Dhaka';
```

**প্রশ্ন ২৫: SQL-এ Stored Procedure-এ Output Parameter কী এবং কীভাবে ব্যবহার করতে হয়?**
**উত্তর:**
সাধারণত Stored Procedure-এ যখন আমরা কোনো প্যারামিটার দিই, তখন আমরা শুধু ডেটাবেসকে কোনো মান (Value) পাস করি (যেমনটি ওপরের প্রশ্নে `@CityName` ছিল)। কিন্তু আমরা যদি চাই যে Stored Procedure কাজ শেষ করে আমাদের কোনো একটি **হিসাব করা ভ্যালু (Calculated Value) ফেরত (Return) দিক**, তখন আমরা **Output Parameter** ব্যবহার করি। 

এটি ঠিক C# এর `out` কিওয়ার্ডের মতো কাজ করে।

**কীভাবে তৈরি ও ব্যবহার করতে হয়?**
ধরুন, আমরা একটি Stored Procedure বানাব, যাকে একটি সিটির নাম দিলে সে আমাদের ওই সিটির **মোট স্টুডেন্ট সংখ্যা** কত, তা গণনা করে ফেরত দেবে।

```sql
-- ১. Output Parameter দিয়ে Procedure তৈরি করা:
CREATE PROCEDURE GetTotalStudentsCount
    @CityName VARCHAR(50),      -- Input Parameter (সিটির নাম দেওয়ার জন্য)
    @TotalCount INT OUTPUT      -- Output Parameter (মোট সংখ্যা ফেরত পাওয়ার জন্য)
AS
BEGIN
    -- COUNT করে রেজাল্টটি @TotalCount ভেরিয়েবলে অ্যাসাইন করা হচ্ছে
    SELECT @TotalCount = COUNT(StudentID) 
    FROM Students 
    WHERE City = @CityName;
END;
```

```sql
-- ২. Procedure টি Execute করা এবং Output টি রিসিভ করা:
DECLARE @ResultCount INT; -- আউটপুট ভ্যালু রিসিভ করার জন্য একটি ভেরিয়েবল বানালাম

EXEC GetTotalStudentsCount 
    @CityName = 'Dhaka', 
    @TotalCount = @ResultCount OUTPUT; 

-- এবার আমরা ফেরত পাওয়া ভ্যালুটি দেখতে পারি:
SELECT @ResultCount AS 'Total Students In Dhaka';
```
*(নোট: Procedure কল করার সময়ও ভেরিয়েবলের নামের শেষে `OUTPUT` কিওয়ার্ডটি লিখতে হয়)।*

**প্রশ্ন ২৬: SQL-এ Trigger কী এবং DML Trigger কীভাবে কাজ করে?**
**উত্তর:**
**Trigger (ট্রিগার)** হলো এক বিশেষ ধরনের Stored Procedure, যা ডেটাবেসের কোনো একটি টেবিলে নির্দিষ্ট কোনো ইভেন্ট (Event) ঘটলে **স্বয়ংক্রিয়ভাবে (Automatically)** রান করে। 
সাধারণ Stored Procedure-কে যেমন আমরা `EXEC` লিখে কল করি, Trigger-কে ম্যানুয়ালি কল করা যায় না। এটি ডেটাবেস ইঞ্জিন নিজেই ফায়ার (Fire) করে।

**DML Triggers কী?**
DML মানে হলো Data Manipulation Language (`INSERT`, `UPDATE`, `DELETE`)। অর্থাৎ টেবিলে ডেটা ইনসার্ট, আপডেট বা ডিলিট হওয়ার সময় যে ট্রিগারগুলো কাজ করে, তাদেরকে DML Triggers বলা হয়।

DML ট্রিগার প্রধানত ব্যবহার করা হয়:
১. **AFTER (বা FOR) Triggers:** ডেটা ইনসার্ট, আপডেট বা ডিলিট সম্পন্ন হওয়ার **পরে** এটি ফায়ার হয়। এটি সাধারণত অডিটিং বা সম্পর্কিত অন্য টেবিল আপডেট করতে ব্যবহৃত হয়।
২. **INSTEAD OF Triggers:** এটি আসল কাজের (Insert/Update/Delete) **পরিবর্তে** ফায়ার হয়। এটি মূলত জটিল ডেটা ভ্যালিডেশন বা View-তে ইনসার্ট করার জন্য ব্যবহৃত হয়।

**Magic Tables (ম্যাজিক টেবিল):**
ট্রিগারের ভেতরে কাজ করার সময় ডেটাবেস সাময়িকভাবে দুটি টেবিল তৈরি করে, যাদেরকে ম্যাজিক টেবিল বলে।
*   **INSERTED:** ইনসার্ট বা আপডেট করার সময় **নতুন ডেটাগুলো** এই টেবিলে জমা হয়।
*   **DELETED:** ডিলিট বা আপডেট করার সময় **পুরোনো ডেটাগুলো** এই টেবিলে জমা হয়।

**সিনট্যাক্স ও উদাহরণ (AFTER INSERT Trigger):**
ধরুন, আমরা চাই `Students` টেবিলে নতুন কোনো স্টুডেন্ট যোগ হলেই ডেটাবেস অটোমেটিক্যালি আমাদের একটি মেসেজ দিক।

```sql
-- Trigger তৈরি করা
CREATE TRIGGER trgAfterInsertStudent
ON Students
AFTER INSERT
AS
BEGIN
    -- এখানে আমরা INSERTED ম্যাজিক টেবিল ব্যবহার করে নতুন ইনসার্ট হওয়া ডেটা দেখতে পারি
    PRINT 'A new student was added successfully!';
END;
```
*(এখন থেকে যখনি `Students` টেবিলে `INSERT` কমান্ড চালানো হবে, এই ট্রিগারটি অটোমেটিক্যালি রান করবে।)*

**প্রশ্ন ২৭: SQL-এ Triggers-এর প্রকারভেদগুলো কী কী এবং INSTEAD OF Trigger বিস্তারিতভাবে কীভাবে কাজ করে?**
**উত্তর:**
SQL Server-এ মূলত তিন ধরনের ট্রিগার থাকে:

১. **DML Triggers (Data Manipulation Language):** যেগুলো `INSERT`, `UPDATE` বা `DELETE` কমান্ডের কারণে ফায়ার হয়। (সাধারণত এগুলোই সবচেয়ে বেশি ব্যবহৃত হয়)।
২. **DDL Triggers (Data Definition Language):** যেগুলো `CREATE`, `ALTER` বা `DROP` কমান্ডের কারণে ফায়ার হয়। ডেটাবেসের স্ট্রাকচার চেঞ্জ করা ঠেকাতে বা অডিট করতে এটি লাগে (যেমন: কেউ যেন টেবিল ড্রপ করতে না পারে)।
৩. **Logon Triggers:** যখন কোনো ইউজার ডেটাবেসে লগইন বা কানেকশন তৈরি করে, তখন এটি ফায়ার হয় (সিকিউরিটির জন্য)।

---
**ডিটেইলস: DML INSTEAD OF Trigger কী এবং কেন লাগে?**

`INSTEAD OF` ট্রিগার হলো এমন একটি ট্রিগার যা আসল কাজটিকে (যেমন: INSERT) স্কিপ করে দিয়ে তার **পরিবর্তে** নিজের ভেতরের লজিক রান করে। 

**কেন ব্যবহার করা হয় (সবচেয়ে বড় ব্যবহার):** 
এর সবচেয়ে বড় ব্যবহার হলো **Complex Views (ভিউ)** এর ক্ষেত্রে। একটি ভিউ যদি একাধিক টেবিল JOIN করে বানানো হয়, তবে আপনি সরাসরি সেই ভিউতে `INSERT` বা `UPDATE` করতে পারবেন না। 
তখন ভিউয়ের ওপর একটি `INSTEAD OF INSERT` ট্রিগার বানানো হয়। ইউজার যখন ভিউতে ইনসার্ট করতে যায়, তখন ডেটাবেস এরর না দিয়ে ট্রিগারটি রান করে। আর ট্রিগারের ভেতরে আমরা লজিক লিখে দিই যে কোন ডেটাটি কোন টেবিলে যাবে (ডেটা ভাগ করে দেওয়া)।

**সিনট্যাক্স ও উদাহরণ (INSTEAD OF INSERT):**
ধরুন, আমরা চাই না কেউ সরাসরি `Employee` টেবিলে ডেটা ইনসার্ট করুক। যদি কেউ ইনসার্ট করার চেষ্টা করে, তবে ডেটা সেভ না হয়ে একটি এরর মেসেজ দেখাবে।

```sql
-- INSTEAD OF Trigger তৈরি করা
CREATE TRIGGER trgInsteadOfInsertEmployee
ON Employee
INSTEAD OF INSERT
AS
BEGIN
    -- ডেটা ইনসার্ট হওয়ার বদলে এই প্রিন্ট মেসেজটি দেখাবে
    PRINT 'You are not allowed to insert data directly into this table.';
END;
```
*(এখন কেউ `INSERT INTO Employee...` কমান্ড দিলে কোনো ডেটা সেভ হবে না, প্রতিক্ষেত্রে উপরের মেসেজটি দেখাবে)।*

**প্রশ্ন ২৮: SQL-এ একাধিক Trigger থাকলে তাদের Execution Order (রান করার সিরিয়াল) কীভাবে সেট করতে হয়?**
**উত্তর:**
ধরুন, আপনার একটি টেবিলে `AFTER INSERT` এর জন্য একই সাথে ৩টি ট্রিগার বানানো আছে। এখন কেউ ডেটা ইনসার্ট করলে ডেটাবেস কোন ট্রিগারটি আগে রান করবে? 

ডিফল্টভাবে SQL Server-এ ট্রিগারগুলো যেকোনো র্যান্ডম অর্ডারে (Random Order) রান হতে পারে। কিন্তু আপনি চাইলে কোন ট্রিগারটি **প্রথম (First)** এবং কোনটি **শেষ (Last)** রান করবে তা ঠিক করে দিতে পারেন।

**কীভাবে সেট করতে হয়?**
এর জন্য SQL Server-এ একটি বিল্ট-ইন স্টোরড প্রসিডিউর আছে, যার নাম `sp_settriggerorder`।

**কিছু নিয়ম বা সীমাবদ্ধতা:**
১. আপনি শুধু `First` এবং `Last` পজিশন বলে দিতে পারবেন। ২য়, ৩য় বা ৪র্থ পজিশন বলে দেওয়ার কোনো উপায় নেই। 
২. ধরুন ৫টি ট্রিগার আছে। আপনি ১টি First এবং ১টি Last সেট করতে পারবেন। মাঝের ৩টি যেকোনো অর্ডারে রান করবে।
৩. `INSTEAD OF` ট্রিগারের জন্য অর্ডার সেট করা যায় না (কারণ একটি টেবিলে/অ্যাকশনে কেবল একটিই `INSTEAD OF` ট্রিগার থাকতে পারে)।

**অর্ডার সেট করার সিনট্যাক্স:**

```sql
-- ১. একটি ট্রিগারকে First (প্রথম) হিসেবে সেট করা:
EXEC sp_settriggerorder 
    @triggername = 'trgFirstInsert', -- আপনার ট্রিগারের নাম
    @order = 'First',                -- First, Last অথবা None হতে পারে
    @stmttype = 'INSERT';            -- কোন অ্যাকশনের জন্য (INSERT/UPDATE/DELETE)

-- ২. একটি ট্রিগারকে Last (শেষ) হিসেবে সেট করা:
EXEC sp_settriggerorder 
    @triggername = 'trgLastInsert', 
    @order = 'Last', 
    @stmttype = 'INSERT';

-- ৩. অর্ডার মুছে ফেলা (আবার র্যান্ডম করে দেওয়া):
EXEC sp_settriggerorder 
    @triggername = 'trgFirstInsert', 
    @order = 'None', 
    @stmttype = 'INSERT';
```

**প্রশ্ন ২৯: SQL-এ View (ভিউ) কী? এর সুবিধা কী এবং ভিউ-এর ওপর কীভাবে Insert, Update ও Delete অপারেশন চালানো যায়?**
**উত্তর:**
**View (ভিউ)** হলো একটি ভার্চুয়াল বা কাল্পনিক টেবিল (Virtual Table)। এটি কোনো ফিজিক্যাল ডেটা নিজে স্টোর করে না (Indexed View ছাড়া)। ভিউ মূলত একটি পূর্বনির্ধারিত SQL কোয়েরি, যা ডেটাবেসে সেভ করা থাকে। যখনই আমরা ভিউ রিড করি, এটি ব্যাকগ্রাউন্ডে আসল টেবিল থেকে ডেটা টেনে এনে আমাদের দেখায়।

**ভিউ ব্যবহারের সুবিধাসমূহ:**
১. **Security (নিরাপত্তা):** আপনি ইউজারকে সরাসরি টেবিলের অ্যাক্সেস না দিয়ে শুধু ভিউয়ের অ্যাক্সেস দিতে পারেন, যাতে তারা সব কলাম (যেমন: Salary বা Password) দেখতে না পারে।
২. **Query Simplification (কোয়েরি সহজ করা):** যদি ৪/৫টি টেবিল JOIN করে একটি বিশাল কোয়েরি লিখতে হয়, তবে তার জন্য একটি ভিউ বানিয়ে রাখলে ডেভেলপাররা কেবল `SELECT * FROM ViewName` লিখেই পুরো ডেটা পেয়ে যাবেন।
৩. **Consistency (ঐক্যবদ্ধতা):** একই কোয়েরি বারবার আলাদা জায়গায় না লিখে ভিউ ব্যবহার করলে কোড ক্লিন থাকে।

---
**ভিউ-এর ওপর Insert, Update এবং Delete (DML Operations):**

হ্যাঁ, ভিউ-এর ওপর `INSERT`, `UPDATE` এবং `DELETE` চালানো সম্ভব, তবে এর জন্য কিছু **কঠোর শর্ত (Conditions)** মানতে হবে:

১. **Single Table Reference:** ভিউটি যদি একাধিক টেবিল JOIN করে বানানো হয়, তবে আপনি একই সাথে একাধিক টেবিলের ডেটা মডিফাই করতে পারবেন না। DML স্টেটমেন্টটি যেকোনো একটি টেবিলেই প্রভাব ফেলতে পারবে।
২. **No Derived/Calculated Columns:** ভিউতে যদি কোনো Aggregate Function (যেমন: SUM, AVG), `DISTINCT`, `GROUP BY` বা কোনো হিসাব করা কলাম (যেমন: `Salary * 0.1`) থাকে, তবে তার ওপর DML রান করা যাবে না।
৩. **NOT NULL columns without default values:** আসল টেবিলে যদি এমন কোনো কলাম থাকে যা `NOT NULL` এবং তার কোনো default মানও সেট করা নেই, তবে সেই কলামটি ভিউতে অবশ্যই উপস্থিত থাকতে হবে। অন্যথায় `INSERT` করার সময় এরর দেখাবে।

**সিনট্যাক্স ও উদাহরণ:**
ধরি, আমাদের `Students` টেবিল থেকে শুধুমাত্র আইডি, নাম এবং সিটির ডেটা নিয়ে একটি সাধারণ ভিউ বানানো আছে:

```sql
-- ১. View তৈরি করা:
CREATE VIEW vwStudentDetails
AS
SELECT StudentID, Name, City
FROM Students;
```

```sql
-- ২. View ব্যবহার করে ডেটা ইনসার্ট (Insert):
INSERT INTO vwStudentDetails (Name, City)
VALUES ('Kamal', 'Chittagong'); 
-- (এটি অটোমেটিক ব্যাকগ্রাউন্ডে Students টেবিলে ইনসার্ট হয়ে যাবে)

-- ৩. View ব্যবহার করে ডেটা আপডেট (Update):
UPDATE vwStudentDetails
SET City = 'Sylhet'
WHERE StudentID = 5;

-- ৪. View ব্যবহার করে ডেটা ডিলিট (Delete):
DELETE FROM vwStudentDetails
WHERE StudentID = 3;
```
*(নোট: ভিউটি যদি খুব বেশি জটিল বা মাল্টিপল টেবিল জয়েন করা হয়ে থাকে, তবে ডিরেক্ট DML এরর দেয়। সেক্ষেত্রে আমরা **`INSTEAD OF` Trigger** ব্যবহার করে ওই DML অপারেশনটি হ্যান্ডেল করি)।*

**প্রশ্ন ৩০: SQL-এ Subquery (সাবকোয়েরি) কী? এটি কয় ধরনের হয় এবং কীভাবে ব্যবহার করতে হয়?**
**উত্তর:**
**Subquery** (যাকে Inner Query বা Nested Query বলা হয়) হলো এমন একটি কোয়েরি যা অন্য একটি SQL কোয়েরির (যাকে Outer Query বলা হয়) ভেতরে অবস্থান করে। এটি সবসময় ব্র্যাকেটের `()` ভেতরে লিখতে হয়।

সহজ কথায়, একটি কোয়েরির ফলাফল যখন আরেকটি কোয়েরিতে ইনপুট হিসেবে পাঠানো হয়, তখন ভেতরের কোয়েরিটিই হলো Subquery। ডেটাবেস প্রথমে ভেতরের Subquery-টি রান করে ফলাফল বের করে এবং সেই ফলাফলের ওপর ভিত্তি করে বাইরের Outer Query-টি রান করে।

**Subquery মূলত ৩ ধরনের হয়:**

১. **Single-Row Subquery:**
    এই সাবকোয়েরিটি কেবল একটি কলাম এবং একটি রো (Single Value) রিটার্ন করে। এটি সাধারণত `=`, `>`, `<`, `>=` ইত্যাদি অপারেটরের সাথে ব্যবহার করা হয়।
```sql
-- যেসব স্টুডেন্টের বয়স গড় (Average) বয়সের চেয়ে বেশি, তাদের ডেটা দেখাবে:
SELECT Name, Age 
FROM Students 
WHERE Age > (SELECT AVG(Age) FROM Students); -- এটি Single-Row Subquery
```

২. **Multi-Row Subquery:**
    এই সাবকোয়েরিটি একাধিক রো (Multiple Rows) রিটার্ন করে। এটি সাধারণত `IN`, `ANY`, `ALL` ইত্যাদি অপারেটরের সাথে ব্যবহার করা হয়।
```sql
-- যারা বিজ্ঞান (Science) বিভাগের কোর্সে ভর্তি হয়েছে, তাদের নাম দেখাবে:
SELECT Name 
FROM Students 
WHERE StudentID IN (SELECT StudentID FROM Enrollments WHERE Department = 'Science');
```

৩. **Correlated Subquery:**
    এটি একটি বিশেষ ধরনের সাবকোয়েরি যা বাইরের (Outer) কোয়েরির ওপর সরাসরি নির্ভরশীল। এখানে বাইরের কোয়েরির প্রতিটি রো বা লাইনের জন্য ভেতরের সাবকোয়েরিটি একবার করে এক্সিকিউট হয় (যা সাধারণ সাবকোয়েরির চেয়ে একটু স্লো কাজ করতে পারে)।
```sql
-- যেসব এমপ্লয়ির স্যালারি তাদের নিজ নিজ ডিপার্টমেন্টের গড় স্যালারির চেয়ে বেশি:
SELECT e.Name, e.Salary, e.Department
FROM Employees e
WHERE e.Salary > (
    SELECT AVG(Salary) 
    FROM Employees 
    WHERE Department = e.Department -- বাইরের টেবিল e এর ওপর নির্ভরশীল
);
```

**প্রশ্ন ৩১: SQL-এ Self-Contained (Independent) Subquery এবং Correlated Subquery-এর মধ্যে মূল পার্থক্য কী?**
**উত্তর:**
সব সাবকোয়েরি একভাবে কাজ করে না। এদের কাজের ধরন এবং ডেটাবেস ইঞ্জিনের প্রসেস করার নিয়মের ওপর ভিত্তি করে এদের প্রধানত এই দুটি ভাগে ভাগ করা হয়:

১. **Self-Contained (Independent) Subquery:**
*   **সংজ্ঞা:** যে সাবকোয়েরিটি সম্পূর্ণ স্বাধীন এবং বাইরের (Outer) কোয়েরির ওপর কোনোভাবেই নির্ভরশীল নয়।
*   **আলাদাভাবে রান করার ক্ষমতা:** এই সাবকোয়েরিটিকে মেইন কোয়েরি থেকে আলাদা করে একা রান করালে এটি সঠিকভাবে আউটপুট দেখাবে।
*   **এক্সিকিউশন ফ্রিকোয়েন্সি:** ডেটাবেস ইঞ্জিন এই সাবকোয়েরিটি পুরো কোয়েরির লাইফসাইকেলে মাত্র **একবার (Once)** রান করে। এর ফলাফলটি মেমরিতে রেখে পরবর্তীতে মেইন কোয়েরি ফিল্টারে বসিয়ে দেওয়া হয়।
*   **উদাহরণ:** 
```sql
SELECT Name FROM Students 
WHERE Age > (SELECT AVG(Age) FROM Students); 
-- এখানে (SELECT AVG(Age) FROM Students) কোয়েরিটি সম্পূর্ণ স্বাধীন। 
-- এটি নিজে রান করে একটি গড় বয়স (যেমন: ২২) বের করবে, এবং মেইন কোয়েরি শুধু দেখবে কাদের বয়স ২২ এর বেশি।
```

২. **Correlated Subquery:**
*   **সংজ্ঞা:** যে সাবকোয়েরিটি মেইন কোয়েরির টেবিল এবং কলামের ওপর সরাসরি নির্ভরশীল। 
*   **আলাদাভাবে রান করার ক্ষমতা:** আপনি যদি এই সাবকোয়েরিটি একা রান করার চেষ্টা করেন, তবে এটি কাজ করবে না এবং এরর দেখাবে (কারণ এটি বাইরের টেবিলের রেফারেন্স ছাড়া কাজ করতে পারে না)।
*   **এক্সিকিউশন ফ্রিকোয়েন্সি:** এটি বাইরের কোয়েরির **প্রতিটি রো-এর জন্য একবার করে (Row-by-Row)** রান হয়। অর্থাৎ বাইরের টেবিলে যদি ১০০০টি রো থাকে, তবে সাবকোয়েরিটিও ১০০০ বার ব্যাকগ্রাউন্ডে এক্সিকিউট হবে।
*   **উদাহরণ:**
```sql
SELECT e.Name, e.Salary, e.Department FROM Employees e
WHERE e.Salary > (SELECT AVG(Salary) FROM Employees WHERE Department = e.Department);
-- এখানে সাবকোয়েরিটির শেষ অংশ (e.Department) বাইরের e টেবিলের রেফারেন্স ব্যবহার করছে। 
-- ফলে এটি প্রতিটি এমপ্লয়ির নিজ ডিপার্টমেন্টের গড় স্যালারি বের করার জন্য বারবার রান হতে বাধ্য।
```

**সহজ সারসংক্ষেপ (Quick Comparison):**

| বৈশিষ্ট্য | Self-Contained Subquery | Correlated Subquery |
| :--- | :--- | :--- |
| **নির্ভরশীলতা** | বাইরের কোয়েরির ওপর নির্ভর করে না। | বাইরের কোয়েরির ওপর সরাসরি নির্ভরশীল। |
| **আলাদাভাবে রান** | একা একা রান করানো সম্ভব। | একা একা রান করানো অসম্ভব (এরর দেবে)। |
| **রান হওয়ার সংখ্যা** | মাত্র ১ বার রান হয়। | বাইরের টেবিলের প্রতিটি রো-এর জন্য ১ বার করে রান হয়। |
| **পারফরম্যান্স** | তুলনামূলক দ্রুত কাজ করে। | ডেটার পরিমাণ অনেক বেশি হলে স্লো হতে পারে। |

**প্রশ্ন ৩২: SQL-এ Scalar Subquery, Multi-Valued Subquery এবং অন্যান্য কী কী ধরনের Subquery হতে পারে?**
**উত্তর:**
সাবকোয়েরি কী ধরনের আউটপুট জেনারেট করছে (কয়টি কলাম ও রো ফেরত দিচ্ছে) তার ওপর ভিত্তি করে এদের প্রধানত ৪টি ভাগে ভাগ করা যায়:

১. **Scalar Subquery:**
*   **সংজ্ঞা:** যে সাবকোয়েরিটি শুধুমাত্র **১টি কলাম এবং ১টি রো (একটি সিঙ্গেল ভ্যালু)** ফেরত দেয়।
*   **কোথায় ব্যবহৃত হয়:** এটি SELECT লিস্টে, WHERE শর্তে বা HAVING শর্তে সাধারণ ভেরিয়েবলের মতো ব্যবহৃত হয় এবং এর সাথে `=`, `>`, `<`, `!=` অপারেটরগুলো চলে।
*   **উদাহরণ:** 
```sql
SELECT Name, (SELECT MAX(Price) FROM Books) AS MaxBookPrice FROM Customers;
-- এটি একটি সিঙ্গেল মান রিটার্ন করবে
```

২. **Multi-Valued (বা Table-Valued) Subquery:**
*   **সংজ্ঞা:** যে সাবকোয়েরিটি **১টি কলাম এবং একাধিক রো (একটি লিস্ট বা ভ্যালুর সেট)** ফেরত দেয়।
*   **কোথায় ব্যবহৃত হয়:** এটি সাধারণত `IN`, `NOT IN`, `ANY`, `ALL` অপারেটরগুলোর সাথে ব্যবহার করা হয়।
*   **উদাহরণ:**
```sql
SELECT Title FROM Books 
WHERE AuthorID IN (SELECT AuthorID FROM Authors WHERE Country = 'Bangladesh');
-- এটি বাংলাদেশের সকল অথরের একটি লিস্ট ফেরত দেবে
```

৩. **Row Subquery:**
*   **সংজ্ঞা:** যে সাবকোয়েরিটি **একাধিক কলাম কিন্তু ঠিক ১টি মাত্র রো** ফেরত দেয়।
*   **কোথায় ব্যবহৃত হয়:** একাধিক কলামের মানকে একসাথে তুলনা করার জন্য এটি ব্যবহৃত হয় (বিশেষ করে PostgreSQL এবং MySQL-এ এটি সাপোর্ট করে)।
*   **উদাহরণ:**
```sql
SELECT Name FROM Students 
WHERE (Age, City) = (SELECT Age, City FROM Instructors WHERE InstructorID = 1);
-- এটি ১ নম্বর ইনস্ট্রাক্টরের বয়স এবং শহরের সাথে স্টুডেন্টের বয়স ও শহর মেলাবে
```

৪. **Table Subquery (বা Derived Table):**
*   **সংজ্ঞা:** যে সাবকোয়েরিটি **একাধিক কলাম এবং একাধিক রো (একটি পূর্ণাঙ্গ টেবিল স্ট্রাকচার)** ফেরত দেয়।
*   **কোথায় ব্যবহৃত হয়:** এটি সাধারণত মেইন কোয়েরির **`FROM`** ক্লজে একটি সাময়িক টেবিল (Derived Table বা CTE) হিসেবে ব্যবহৃত হয় এবং এর সাথে একটি Alias বা ছদ্মনাম দিতে হয়।
*   **উদাহরণ:**
```sql
SELECT TempTable.Name, TempTable.Age 
FROM (SELECT Name, Age FROM Students WHERE Age > 20) AS TempTable;
-- এখানে TempTable একটি সাময়িক টেবিল হিসেবে কাজ করছে
```

**প্রশ্ন ৩৩: SQL-এ Joins (জয়েন) কী? Joins কত প্রকার এবং এরা কীভাবে কাজ করে? (সবগুলোর উদাহরণসহ)**
**উত্তর:**
রিলেশনাল ডেটাবেসে ডেটা সাধারণত বিভিন্ন টেবিলে আলাদা করে রাখা হয় (Data Normalization এর নিয়ম অনুযায়ী)। **Joins** হলো এমন একটি পদ্ধতি, যার মাধ্যমে দুটি বা তার বেশি টেবিলকে তাদের মধ্যে থাকা একটি সাধারণ কলামের (যেমন প্রাইমারি বা ফরেন কী) ওপর ভিত্তি করে সংযুক্ত করে ডেটা তুলে আনা যায়।

আমরা নিচের দুটি কাল্পনিক টেবিল ধরে উদাহরণগুলো বুঝবো:
*   **Students টেবিল:**
    | StudentID | Name | DeptID |
    | :--- | :--- | :--- |
    | 1 | Rahim | 101 |
    | 2 | Karim | 102 |
    | 3 | Salam | NULL |

*   **Departments টেবিল:**
    | DeptID | DeptName |
    | :--- | :--- |
    | 101 | CSE |
    | 102 | EEE |
    | 103 | BBA |

---

### ১. INNER JOIN (অথবা শুধু JOIN)
*   **কাজ:** এটি শুধুমাত্র সেইসব রেকর্ডগুলো ফেরত দেয়, যেগুলো **উভয় টেবিলেই ম্যাচ (মিল) করে**। কোনো ম্যাচিং না থাকলে তা বাদ পড়ে যাবে।
*   **সিনট্যাক্স ও উদাহরণ:**
```sql
SELECT s.Name, d.DeptName
FROM Students s
INNER JOIN Departments d ON s.DeptID = d.DeptID;
```
*   **আউটপুট:**
    | Name | DeptName |
    | :--- | :--- |
    | Rahim | CSE |
    | Karim | EEE |
    *(যেহেতু Salam-এর কোনো DeptID নেই এবং BBA ডিপার্টমেন্টে কোনো স্টুডেন্ট নেই, তাই এরা বাদ পড়েছে)*

---

### ২. LEFT JOIN (অথবা LEFT OUTER JOIN)
*   **কাজ:** এটি বামদিকের (Left) টেবিলের **সবগুলো রেকর্ড** ফেরত দেবে এবং ডানদিকের (Right) টেবিলের সাথে ম্যাচ করা রেকর্ডগুলো যুক্ত করবে। ডানদিকের টেবিলে মিল না থাকলে সেখানে `NULL` দেখাবে।
*   **সিনট্যাক্স ও উদাহরণ:**
```sql
SELECT s.Name, d.DeptName
FROM Students s
LEFT JOIN Departments d ON s.DeptID = d.DeptID;
```
*   **আউটপুট:**
    | Name | DeptName |
    | :--- | :--- |
    | Rahim | CSE |
    | Karim | EEE |
    | Salam | NULL |
    *(এখানে Salam-এর ডিপার্টমেন্ট নেই, তবুও সে এসেছে এবং DeptName কলামটি NULL দেখাচ্ছে)*

---

### ৩. RIGHT JOIN (অথবা RIGHT OUTER JOIN)
*   **কাজ:** এটি LEFT JOIN এর ঠিক উল্টো। এটি ডানদিকের (Right) টেবিলের **সবগুলো রেকর্ড** ফেরত দেয় এবং বামদিকের (Left) টেবিলের ম্যাচ করা রেকর্ডগুলো নিয়ে আসে। বামদিকের টেবিলে মিল না থাকলে সেখানে `NULL` দেখাবে।
*   **সিনট্যাক্স ও উদাহরণ:**
```sql
SELECT s.Name, d.DeptName
FROM Students s
RIGHT JOIN Departments d ON s.DeptID = d.DeptID;
```
*   **আউটপুট:**
    | Name | DeptName |
    | :--- | :--- |
    | Rahim | CSE |
    | Karim | EEE |
    | NULL | BBA |
    *(এখানে BBA ডিপার্টমেন্টের কোনো স্টুডেন্ট নেই, তাও BBA এসেছে এবং Name কলামে NULL দেখাচ্ছে)*

---

### ৪. FULL JOIN (অথবা FULL OUTER JOIN)
*   **কাজ:** এটি বাম এবং ডান **উভয় টেবিলেরই সব ডেটা** ফেরত দেবে। যেখানে ম্যাচ করবে সেখানে ডেটা জোড়া লাগবে, আর যেখানে ম্যাচ করবে না সেখানে অপর টেবিলের ডেটার জায়গায় `NULL` বসবে।
*   **সিনট্যাক্স ও উদাহরণ:**
```sql
SELECT s.Name, d.DeptName
FROM Students s
FULL JOIN Departments d ON s.DeptID = d.DeptID;
```
*   **আউটপুট:**
    | Name | DeptName |
    | :--- | :--- |
    | Rahim | CSE |
    | Karim | EEE |
    | Salam | NULL |
    | NULL | BBA |

---

### ৫. CROSS JOIN
*   **কাজ:** এটি দুটি টেবিলের প্রতিটি রোর সাথে অপর টেবিলের প্রতিটি রোর সম্ভাব্য সব ধরনের কম্বিনেশন তৈরি করে (একে **Cartesian Product** বলা হয়)। এখানে কোনো `ON` ক্লজ বা ম্যাচিং কন্ডিশন লাগে না।
*   **সিনট্যাক্স ও উদাহরণ:**
```sql
SELECT s.Name, d.DeptName
FROM Students s
CROSS JOIN Departments d;
```
*   **আউটপুট:** (মোট ৩ স্টুডেন্ট × ৩ ডিপার্টমেন্ট = ৯টি সারি তৈরি হবে)
    *   Rahim - CSE, Rahim - EEE, Rahim - BBA
    *   Karim - CSE, Karim - EEE, Karim - BBA... ইত্যাদি।

---

### ৬. SELF JOIN
*   **কাজ:** যখন একটি টেবিলকে **নিজের সাথেই JOIN করা হয়**, তখন তাকে SELF JOIN বলা হয়। মূলত টেবিলের ভেতরের ডেটাগুলোর মধ্যে হায়ারার্কিকাল রিলেশন (যেমন: এমপ্লয়ি এবং তার ম্যানেজার, উভয়ই এক টেবিলেই এমপ্লয়ি) তৈরি করার জন্য এটি করা হয়।
*   **সিনট্যাক্স ও উদাহরণ:**
```sql
-- Employees (EmpID, Name, ManagerID) টেবিল থেকে ম্যানেজার ও এমপ্লয়ির নাম একসাথে দেখা:
SELECT e1.Name AS 'Employee', e2.Name AS 'Manager'
FROM Employees e1
INNER JOIN Employees e2 ON e1.ManagerID = e2.EmpID;
```

**প্রশ্ন ৩৪: ORM, CRM, CMS এবং ERP এর মধ্যে পার্থক্য কী?**
**উত্তর:**
*   **ORM (Object-Relational Mapping):** ডেটাবেসের সাথে কোডের মাধ্যমে (Raw SQL না লিখে) কথা বলার একটি প্রোগ্রামিং টেকনিক। (উদাহরণ: Entity Framework)।
*   **CRM (Customer Relationship Management):** কাস্টমারদের তথ্য, সেলস ও মার্কেটিং ম্যানেজ করার বিজনেস সফটওয়্যার। (উদাহরণ: Salesforce, HubSpot)।
*   **CMS (Content Management System):** কোনো কোডিং জ্ঞান ছাড়া ওয়েবসাইট বানানোর এবং কন্টেন্ট পাবলিশ করার প্ল্যাটফর্ম। (উদাহরণ: WordPress, Shopify)।
*   **ERP (Enterprise Resource Planning):** কোম্পানির ফাইন্যান্স, HR, সাপ্লাই চেইন সবকিছু এক জায়গায় ম্যানেজ করার সেন্ট্রাল সফটওয়্যার। (উদাহরণ: SAP, Oracle)।

**প্রশ্ন ৩৫: .NET ইকোসিস্টেমে ADO.NET, Dapper এবং Identity Core কী?**
**উত্তর:**
*   **ADO.NET:** .NET-এ ডেটাবেস কানেক্ট করার সবচেয়ে বেসিক ও কোর উপায়। এখানে Raw SQL নিজে লিখতে হয় এবং ডেটা ম্যানুয়ালি রিড করতে হয়।
*   **Dapper:** এটি একটি Micro-ORM। এটি অনেক ফাস্ট। এখানে SQL কোয়েরি নিজে লিখতে হয়, কিন্তু ডেটাবেসের রেজাল্টটি অটোম্যাটিক C# অবজেক্টে ম্যাপ হয়ে যায়।
*   **Identity Core:** এটি .NET-এর ইউজার লগইন, রেজিস্ট্রেশন, পাসওয়ার্ড হ্যাশিং এবং সিকিউরিটি (Role/Token) ম্যানেজ করার একটি বিল্ট-ইন রেডিমেড ফ্রেমওয়ার্ক।

### LINQ (Language Integrated Query)

**প্রশ্ন ৩৬: LINQ কী?**
**উত্তর:** LINQ হলো C# এর এমন একটি পাওয়ারফুল ফিচার, যা দিয়ে আলাদা করে SQL না শিখে সরাসরি C# কোড দিয়েই যেকোনো ডেটা সোর্স (List, Array, Database, XML) থেকে ডেটা ফিল্টার বা কোয়েরি করা যায়।

**প্রশ্ন ৩৭: LINQ-এ কতগুলো কী-ওয়ার্ড বা অপারেটর আছে?**
**উত্তর:** LINQ লেখার দুটি উপায় আছে:
১. **Query Syntax:** এতে ১২-১৫টি কী-ওয়ার্ড থাকে। যেমন: `from`, `where`, `select`, `join`, `orderby`।
২. **Method Syntax (Lambda):** এতে প্রায় ৫০+ টি মেথড (Standard Query Operators) থাকে। যেমন: `Where`, `Select`, `FirstOrDefault`, `Count`, `Any`।

**প্রশ্ন ৩৮: LINQ-এর ফুল এক্সিকিউশন লাইফসাইকেল কী?**
**উত্তর:** একটি LINQ কোয়েরি ৪টি ধাপে কাজ করে:
১. **Definition:** প্রথমে কোয়েরি লেখা হয় (এই ধাপে ডেটাবেসে কোনো কল যায় না)।
২. **Translation:** LINQ Provider (যেমন EF Core) আপনার C# কোডটিকে Raw SQL-এ ট্রান্সলেট করে।
৩. **Execution (Deferred Execution):** যখন কোয়েরিটিকে `foreach` লুপে চালানো হয় বা শেষে `.ToList()` কল করা হয়, ঠিক তখনই এটি ডেটাবেসে হিট করে এক্সিকিউট হয়। একে দেরিতে রান হওয়া বা Deferred Execution বলে।
４. **Materialization:** ডেটাবেস থেকে কাঁচা (Raw) ডেটা ফেরত আসে এবং তা C# অবজেক্টে (যেমন List<User>) কনভার্ট হয়ে আপনার কাছে পৌঁছায়।
